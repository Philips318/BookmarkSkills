#无障碍标准

web应用程序开发的综合可访问性规则。每个反模式都包括严重性分类、检测方法、WCAG 2.2参考和纠正代码示例。

* *严重性级别:* *

- **关键** -用户无法访问内容。必须在合并前修复。
- **重要** -辅助技术用户的重大障碍。在相同的冲刺中修复。
- **建议** -提高辅助技术的可用性。为将来的迭代做计划。

ARIA的五项规则1. **首选原生HTML** -使用`<button>`而不是`<div role="button">`。原生元素具有内置的键盘、焦点和语义。
2. **不要在禁止的地方更改本机语义** -不要将`role="heading"`添加到`<button>`。使用正确的元素。
3. **所有ARIA控件必须是键盘可操作的** -如果`role="button"`，处理Enter和空格键事件。
4. **不要在可对焦元素上使用`aria-hidden="true"`-隐藏于辅助技术但仍然可对焦会创建一个“鬼”元素。
5. **所有交互元素需要一个可访问的名称** -通过标签，`aria-label`,`aria-labelledby`，或可见的文本内容。

语义HTML反模式（S1-S8）`<html>`上缺少`lang`属性

—**严重性**：紧急
- **检测**:`<html`无`lang=`- ** wcag **: 3.1.1 (a)```html
<!-- BAD -->
<html>

<!-- GOOD -->
<html lang="en">
```
Next.js：在`app/layout.tsx`中设置。Angular：在`src/index.html`中设置。Vue/Nuxt：在`app.vue`或`nuxt.config`中设置。

### S2：多个`<h1>`每页

—**严重性**：建议
- **检测**：多个`<h1>`元素，使页面标题结构不清晰
- **WCAG**：最佳实践（支持1.3.1）

建议每页用一个`<h1>`表示主题。区段使用`<h2>`。多个`<h1>`元素并不严格违反WCAG，但可能会混淆屏幕阅读器导航。

### S3：标题水平间隙

- **严重性**：重要
- **检测**:`<h1>`后接`<h3>`（跳过`<h2>`）
- ** wcag **: 1.3.1 (a)

维护逻辑嵌套：`h1 > h2 > h3 > h4`。用CSS样式化标题，而不是选择不同的标题级别。

Div汤-没有地标元素- **严重性**：重要
- **检测**：页面只使用`<div>`，不使用`<nav>`，`<main>`,`<header>`,`<footer>`- **WCAG**：最佳实践（支持1.3.1,2.4.1）```html
<!-- GOOD -->
<header>...</header>
<nav aria-label="Main">...</nav>
<main>...</main>
<footer>...</footer>
```
### S5：布局表没有`role="presentation"`- **严重性**：重要
- **检测**:`<table>`，不含`<th>`、`<caption>`、`role="presentation"`- ** wcag **: 1.3.1 (a)

使用CSSGrid/Flexbox进行布局。如果必须使用表进行布局，则添加`role="presentation"`。

### S6：没有头的数据表

—**严重性**：紧急
- **检测**:`<table>`有数据行，但没有`<th>`元素
- ** wcag **: 1.3.1 (a)```html
<!-- GOOD -->
<table>
  <caption>User list</caption>
  <thead>
    <tr><th scope="col">Name</th><th scope="col">Email</th></tr>
  </thead>
  <tbody>
    <tr><td>Alice</td><td>alice@example.com</td></tr>
  </tbody>
</table>
```
### S7：非描述性链接文本

- **严重性**：重要
—**检测**:`>click here<|>read more<|>learn more<|>here<|>more<|>link<`- ** wcag **: 2.4.4 (a)```html
<!-- BAD -->
<a href="/pricing">Click here</a>

<!-- GOOD -->
<a href="/pricing">View pricing plans</a>
```
### S8：没有语义HTML的交互元素

—**严重性**：紧急
—**检测**:`<div.*(?:onClick|@click|\(click\))`- ** wcag **: 4.1.2 (a)```tsx
// BAD — not focusable, no role, no keyboard support
<div onClick={handleClick}>Submit</div>

// GOOD
<button onClick={handleClick}>Submit</button>
```

ARIA反模式（A1-A8）

原生元素上的冗余ARIA

—**严重性**：建议
—**检测**:`<button.*role="button"|<nav.*role="navigation"|<a.*role="link"`**WCAG**: ARIA规则2

删除多余的ARIA。`<button>`已经有`role="button"`。

### A2:`aria-hidden="true"`的可聚焦元素

—**严重性**：紧急
- **检测**:`aria-hidden="true"`对焦元素（按钮，输入，a, [tabindex]）
- **WCAG**: ARIA规则

不要在`aria-hidden="true"`内容中留下可聚焦的元素，也不要在可聚焦的元素上使用`aria-hidden="true"`。相反，对于支持它的本机控件，如`<button>`或`<input>`，如果想禁用该控件，则使用`disabled`。对于`<a>`元素或使用`[tabindex]`可调焦的任意元素，请删除可调焦性（例如，删除`href`或`tabindex`）。如果内容应该完全非交互式且不受辅助技术的影响，则使用`inert`、`hidden`，或者将其从DOM中删除。缺少必需的ARIA属性

—**严重性**：紧急
**检测**:`role="tab"`不带`aria-selected`，`role="checkbox"`不带`aria-checked`- ** wcag **: 4.1.2 (a)

每个角色需要：`tab`需要`aria-selected`；`combobox`需要`aria-expanded`/`aria-controls`；`slider`需要`aria-valuemin`/`aria-valuemax`/`aria-valuenow`；`checkbox`需要`aria-checked`。

无效的ARIA角色值

—**严重性**：紧急
—**检测**：不存在值的`role="[^"]*"`- ** wcag **: 4.1.2 (a)

辅助技术会忽略无效的角色。常见错误：`role="input"`，`role="text"`，拼写错误。

### A5: ARIA原生HTML工作

- **严重性**：重要
**检测**:`role="button"`对`<div>`，`role="checkbox"`对`<div>`- **WCAG**: ARIA规则```html
<!-- BAD — requires manual keyboard, focus, and state management -->
<div role="checkbox" aria-checked="false" tabindex="0">Accept terms</div>

<!-- GOOD — all behavior built-in -->
<label><input type="checkbox" /> Accept terms</label>
```
### A6：图标按钮缺少`aria-label`—**严重性**：紧急
- **检测**:`<button`与SVG/icon子，没有文本或`aria-label`- ** wcag **: 4.1.2 (a)```html
<!-- GOOD -->
<button aria-label="Close dialog"><svg aria-hidden="true">...</svg></button>
```
### A7:`role="presentation"`对焦元素

- **严重性**：重要
- **检测**:`role="presentation"`对交互元素
- **WCAG**: ARIA规则

浏览器将忽略可聚焦元素上的表示角色。

### A8：动态内容缺少活动区域

- **严重性**：重要
- **检测**：不含`role="alert"`、`role="status"`、`aria-live`的Toast/notification组件
- ** wcag **: 4.1.3 （aa）```html
<!-- GOOD — content announced when content is injected into a preexisting live region element in the DOM -->
<div role="status" aria-live="polite">Item saved successfully</div>
<!-- Use role="alert" (assertive) for errors -->
<div role="alert">Failed to save. Please try again.</div>
```

键盘和焦点反模式（K1-K7）

### K1:`onClick`在非原生元素上没有`onKeyDown`—**严重性**：紧急
- **检测**:`(?:onClick|@click|\(click\))`对`<div>`或`<span>`没有键盘处理程序
- ** wcag **: 2.1.1 (a)

请使用`<button>`。如果需要一个div：添加`role="button"`，`tabIndex={0}`，处理Enter和空格键激活。

### K2：正`tabindex`值

—**严重性**：紧急
- **检测**:`(?:tabindex="[1-9]\d*"|tabIndex=\{[1-9]\d*\})`- ** wcag **: 2.4.3 (a)

只使用`tabindex="0"`（添加到制表符顺序）和`tabindex="-1"`（仅编程焦点）。

### K3：聚焦陷阱没有逃脱

—**严重性**：紧急
- **检测**:Modal/overlay没有Escape键处理程序或焦点捕获
- ** wcag **: 2.1.2 (a)使用原生`<dialog>`和`showModal()`-它可以防止键盘焦点移动到惰性的非对话框内容。此外，它还内置了用于解散的Escape键，并且焦点将自动返回到调用元素（如果可用）。如果需要自定义模态对话框实现：在对话框中使用陷阱选项卡或对非对话框内容使用`inert`属性（不要在包含对话框的元素上使用`inert`），在Escape时解散（除非用户必须确认操作），在关闭时将焦点返回到触发元素，或者在解散时触发元素不再存在时将焦点返回到最佳逻辑位置。

### K4：缺少跳过链接

- **严重性**：重要
- **检测**：没有跳转链接作为第一个可聚焦的元素
- ** wcag **: 2.4.1 (a)```html
<a href="#main-content" class="skip-link">Skip to main content</a>
<nav>...</nav>
<main id="main-content" tabindex="-1">...</main>
```

```css
.skip-link { position: absolute; top: -40px; left: 0; padding: 8px 16px; background: #000; color: #fff; z-index: 100; }
.skip-link:focus { top: 0; }
```
### K5:`outline: none`无需更换

—**严重性**：紧急
- **检测**:`outline:\s*none|outline:\s*0\b`，不替换`:focus-visible`- ** wcag **: 2.4.7 （aa）```css
/* GOOD */
button:focus-visible { outline: 2px solid #005fcc; outline-offset: 2px; }
```
### K6：仅鼠标交互

- **严重性**：重要
- **检测**:`onMouseOver|onMouseEnter|@mouseenter`没有键盘等效
- ** wcag **: 2.1.1 (a)

将悬停与焦点事件配对。使用`onFocus`/`onBlur`和`onMouseEnter`/`onMouseLeave`。

自定义模态关闭后不返回焦点

- **严重性**：重要
- **检测**：自定义模态对话框关闭不恢复焦点触发
- ** wcag **: 2.4.3 (a)

如果关闭时触发元素不再存在，则存储对触发元素或最佳逻辑位置的引用。在模态关闭时，调用`triggerElement.focus()`。

##创建反模式（F1-F6）

### F1：没有关联标签的输入

—**严重性**：紧急
- **检测**：不含`<label>`、`aria-label`、`aria-labelledby`的`<input|<select|<textarea`- ** wcag **: 1.3.1 (a), 3.3.2 (a)```html
<!-- GOOD -->
<label for="email">Email address</label>
<input id="email" type="email" placeholder="you@example.com" />
```
### F2：错误消息没有链接到输入

—**严重性**：紧急
- **检测**：输入附近没有`aria-describedby`的错误元素
- ** wcag **: 3.3.1 (a)```html
<input id="email" type="email" aria-describedby="email-error" aria-invalid="true" />
<span id="email-error" class="error">Invalid email format</span>
```
### F3：必填字段仅由颜色或`*`表示

- **严重性**：重要
- **检测**:`required`或`*`不带`aria-required="true"`或HTML`required`- ** wcag **: 3.3.2 (a), 1.4.1 (a)```html
<label for="name">Name <span aria-hidden="true">*</span></label>
<input id="name" type="text" required />
<p class="form-note">Fields marked * are required</p>
```
### F4：没有错误总结或关注第一个错误

- **严重性**：重要
- **检测**：表单提交处理程序没有验证失败的焦点管理
- ** wcag **: 3.3.1 (a)

在提交失败时，关注第一个无效字段或显示并关注错误摘要。

### F5：没有可访问的替代CAPTCHA

- **严重性**：重要
- **检测**:Puzzle/image无回退captcha；密码字段使用`autocomplete='off'`或粘贴阻止JavaScript
- ** wcag **: 3.3.8 （aa）

使用reCAPTCHA v3（不可见），hCaptcha可访问模式，或替代认证。永远不要阻止粘贴或自动填充密码字段-这违反了WCAG 3.3.8。

### F6：占位符作为标签

- **严重性**：重要
- **检测**:`placeholder=`，不附带`<label>`，`aria-label`或`aria-labelledby`- ** wcag **: 3.3.2 (a)

总是将占位符与可见的`<label>`配对。占位符是一个提示，而不是一个标签。

---视觉和颜色反图案（V1-V5）

文本对比度不足

—**严重性**：紧急
- **检测**：文字颜色组合低于4.5:1（正常）或3:1（大）
- ** wcag **: 1.4.3 （aa）```css
/* BAD — #999 on #fff is ~2.5:1 */
.text { color: #999; background: #fff; }

/* GOOD — #595959 on #fff is 7.0:1 */
.text { color: #595959; background: #fff; }
```
### V2：仅由颜色传达的信息

—**严重性**：紧急
- **检测**:Error/success状态仅通过颜色区分
- ** wcag **: 1.4.1 (a)

添加辅助指示器：图标、文本、图案、下划线或边框。

### V3：固定字体大小防止调整大小

- **严重性**：重要
- **检测**:`font-size:\s*[0-9]*px`（不含root/base）
- ** wcag **: 1.4.4 （aa）

使用`rem`或`em`设置字体大小。基础字体可以是`px`，但内容字体应该是相对的。

### V4: 320px的内容不回流

- **严重性**：重要
- **检测**：固定宽度的容器，在窄的宽度水平滚动
- ** wcag **: 1.4.10 （aa）

使用响应式布局（Grid, Flexbox）。以320px的CSS宽度测试。避免固定宽度的容器。

### V5：动画没有`prefers-reduced-motion`—**严重性**：建议
- **检测**:`animation:|transition:`无`prefers-reduced-motion`媒体查询
- ** wcag **: 2.3.3 （aaa）最佳实践和AAA增强。在`prefers-reduced-motion`后面添加非必要的动画，这样请求较少运动的用户就不会被迫体验交互触发的效果。```css
@media (prefers-reduced-motion: no-preference) {
  .card { transition: transform 0.3s ease; }
  .card:hover { transform: scale(1.05); }
}
