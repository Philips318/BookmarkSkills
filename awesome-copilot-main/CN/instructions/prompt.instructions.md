#副驾驶提示文件指南

创建有效且可维护的提示文件的说明，指导GitHub Copilot跨任何存储库交付一致的高质量结果。

##范围和原则
-目标受众：为Copilot Chat编写可重用提示的维护者和贡献者。
-目标：可预测的行为，明确的期望，最小的权限，以及跨存储库的可移植性。
-主要参考：关于提示文件和组织特定约定的VS Code文档。

## Frontmatter需求

每个提示文件都应该包含以下字段的YAML标题：Required/Recommended字段

|字段|必选|描述||-------|----------|-------------|
|`description`|推荐|提示的简短描述（单句，可操作的结果）|
|`name`|可选|在聊天中输入`/`后显示的名称。如果没有指定|，默认为filename
|`agent`|推荐|使用的代理名称：`ask`、`edit`、`agent`或自定义代理名称。默认为当前代理|
|`model`|可选|使用的语言模型。默认为当前选择的模型|
|`tools`|可选|可用于此提示符的tool/tool集合名称列表|
|`argument-hint`|可选|聊天输入中显示的提示文本，用于指导用户交互|

# # #的指导方针-使用一致的引号（建议单引号），每行保留一个字段，以提高可读性和版本控制的清晰度
—若指定的座席为`tools`，且当前座席为`ask`或`edit`，则默认座席为`agent`-保留您的组织所需的任何额外元数据（`language`,`tags`，`visibility`等）

##文件命名和放置
-使用以`.prompt.md`结尾的kebab-case文件名，并将它们存储在`.github/prompts/`下，除非您的工作空间标准指定了另一个目录。
—提供一个简短的文件名来传达操作（例如，`generate-readme.prompt.md`而不是`prompt1.prompt.md`）。##车身结构
-从与提示意图相匹配的`#`级标题开始，以便在快速选择搜索中表现良好。
-用可预测的部分组织内容。推荐基线：`Mission`或`Primary Directive`、`Scope & Preconditions`、`Inputs`、`Workflow`（逐步）、`Output Expectations`和`Quality Assurance`。
-调整部分名称以适应域，但保留逻辑流程：为什么→上下文→输入→操作→输出→验证。
-使用相关链接引用相关提示或指令文件，以帮助发现。输入和上下文处理
-使用`${input:variableName[:placeholder]}`作为所需值，并说明用户何时必须提供这些值。在可能的情况下提供默认值或替代方案。
-仅在必要时才调用上下文变量，如`${selection}`，`${file}`,`${workspaceFolder}`，并描述副驾驶应该如何解释它们。
-记录当缺少强制上下文时如何进行（例如，“请求文件路径并在未定义时停止”）。

##工具和权限指导
—将`tools`限制为允许该任务的最小集合。当顺序重要时，按首选执行顺序列出它们。
—如果提示符从聊天模式继承了工具，请提及这种关系，并说明任何重要的工具行为或副作用。
-对破坏性操作（文件创建，编辑，终端命令）发出警告，并在工作流程中包含护栏或确认步骤。##指令语气和风格
-写直接的，祈使句针对副驾驶（例如，“分析”，“生成”，“总结”）。
-保持句子简短，明确，遵循谷歌开发人员文档翻译最佳实践，以支持本地化。
-避免习语、幽默或特定文化的引用；使用中立、包容的语言。

##输出定义
—指定预期结果的格式、结构和位置（例如，“使用下面的模板创建`docs/adr/adr-XXXX.md`”）。
-包括成功标准和失败触发器，以便副驾驶知道何时停止或重试。
提供验证步骤——手动检查、自动命令或验收标准列表——评审者可以在运行提示符后执行这些步骤。示例和可重用资产
-嵌入Good/Bad示例或脚手架（Markdown模板，JSON存根），提示符应该产生或遵循。
-内联维护参考表（功能、状态码、角色描述），以保持提示自包含。当上游资源发生变化时，更新这些表。
-链接到权威文件，而不是复制冗长的指导。质量保证检查表
-[]前缘油田是完整的，准确的，最低特权的。
-[]输入包括占位符，默认行为和回退。
-[]工作流包括准备、执行和后处理，没有间隙。
-[]输出期望包括格式和存储细节。
-[]验证步骤是可操作的（命令，diff检查，审查提示）。
—[]提示符引用的安全、合规和隐私策略是当前的。
—[]典型场景下，VS Code（`Chat: Run Prompt`）执行成功。##维护指导
-版本控制提示与他们影响的代码；当依赖项、工具或评审过程发生变化时，更新它们。
-定期检查提示，以确保工具列表、模型需求和链接文档保持有效。
-与其他存储库协调：当一个提示被证明非常有用时，将通用指导提取到指令文件或共享提示包中。
