SQL开发

数据库模式生成
-所有表名都应该是单数形式
-所有的列名应该是单数形式
-所有表都应该有一个名为`id`的主键列
-所有表都应该有一个名为`created_at`的列来存储创建时间戳
-所有表都应该有一个名为`updated_at`的列来存储上次更新的时间戳

数据库模式设计
-所有表都应该有一个主键约束
-所有外键约束都应该有一个名称
-所有外键约束应该内联定义
-所有外键约束应该有`ON DELETE CASCADE`选项
-所有外键约束应该有`ON UPDATE CASCADE`选项
-所有外键约束应该引用父表的主键SQL编码风格
SQL关键字（SELECT， FROM， WHERE）使用大写
-对嵌套查询和条件使用一致的缩进
-包括注释来解释复杂的逻辑
-将长查询分成多行以提高可读性
-一致地组织子句（SELECT， FROM， JOIN， WHERE, GROUP BY， HAVING, ORDER BY）

SQL查询结构
-在SELECT语句中使用显式列名，而不是SELECT *
-当使用多个表时，用表名或别名限定列名
-当可以使用连接时，限制使用子查询
-包括LIMIT/TOP子句来限制结果集
-对频繁查询的列使用适当的索引
避免在WHERE子句中的索引列上使用函数存储过程命名约定
存储过程名称前加“usp_”
-存储过程名称使用PascalCase
-使用说明目的的描述性名称（例如，usp_GetCustomerOrders）
-在返回多个记录时包含复数名词（例如，usp_GetProducts）
-在返回单个记录时包含单数名词（例如，usp_GetProduct）

##参数处理
-在参数前加上“@”
-参数名称使用驼峰大小写
-可选参数提供默认值
-参数值在使用前需要验证
-文档参数与注释
-一致地安排参数（首先是必需的，之后是可选的）存储过程结构
-包括头注释块的描述，参数和返回值
-返回标准化误差codes/messages-返回列顺序一致的结果集
-使用OUTPUT参数返回状态信息
-在临时表前加上‘tmp_’


SQL安全最佳实践
—参数化所有查询，防止SQL注入
—执行动态SQL时使用准备好的语句
-避免在SQL脚本中嵌入凭据
-在不暴露系统细节的情况下实现适当的错误处理
避免在存储过程中使用动态SQL

##事务管理
-显式地开始和提交事务
-根据要求使用适当的隔离级别
避免长时间运行的事务锁住表
-使用批处理大数据操作
-为修改数据的存储过程添加SET NOCOUNT ON
