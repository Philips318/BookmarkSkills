# Markdown无障碍审查指南

在审查markdown文件时，根据GitHub的[使你的GitHub配置文件页面可访问的5个技巧]（https://github.blog/developer-skills/github/5-tips-for-making-your-github-profile-page-accessible/）和Smashing杂志的文章[提高markdown的可访问性]（https://www.smashingmagazine.com/2021/09/improving-accessibility-of-markdown/）检查以下可访问性问题。标记违规并建议修复，并明确解释可访问性影响。

# # 1。描述性的链接

-标记通用链接文本，如“点击这里”，“在这里”，“这个”，“阅读更多”或“链接”。
链接文本在脱离上下文时必须有意义，因为辅助技术可以将链接呈现为一个孤立的列表。
-标记同一页面上的多个链接，共享相同的文本，但指向不同的目的地。
-在散文裸url应转换为描述性链接。

缺点:`Read my blog post [here](https://example.com)`好:`Read my blog post "[Crafting an accessible resume](https://example.com)"`# # 2。图像替代（alt）文本-标记图像与空的alt文本（例如，`![](path/to/image.png)`），除非他们明确装饰。
标记文件名（例如，`img_1234.jpg`）或通用占位符（例如，`screenshot`,`image`）的所有文本。
-所有文本应该简洁和描述性。包括图像中可见的任何文本。
-在相关的地方使用“截图”，但不要加上“image of”的前缀，因为屏幕阅读器会自动宣布。
-对于复杂的图像（图表，信息图表），建议在所有文本中总结数据，并通过`<details>`标签或链接内容提供更长的描述。
当提出所有文本改进建议时，将其作为建议提交给作者审阅。Alt文本需要理解视觉内容和上下文，只有作者才能正确评估。

# # 3。标题层次结构—每个文档只能有一个H1 (`#`)，用作页面标题。注意：在项目中，H1是自动从标题生成的，从H2开始。
标题必须遵循逻辑层次结构，不能跳过级别（例如，`##`后面跟着`####`是违规的）。
-标志粗体文本（`**text**`），用作适当标题的视觉替代。
-适当的标题结构允许辅助技术用户按节导航，并帮助视力正常的用户扫描内容。

# # 4。平实的语言-标记可以简化的不必要的复杂或术语较多的语言。
使用短句、常用词和主动语态。
-标记长而密集的段落，这些段落可以分成更小的部分或列表。
-在描述UI导航时，首先用简单的语言将操作写成顺序步骤（例如，“打开设置，然后选择首选项”）。使用通用的、稳定的标签，而不是图标名称或视觉描述。
-插入的视觉参考可以作为补充上下文（例如，“（齿轮图标>偏好）”），但永远不要使用视觉面包屑表示法或图标名称作为描述导航路径的唯一方式。
当提出简单的语言改进建议时，将其作为建议呈现给作者进行审查。语言决策需要理解听众、语境和语气。

# # 5。列表和表情符号的使用

# # #列表-旗帜表情符号或特殊字符用作项目符号，而不是适当的标记列表语法（`-`,`*`,`+`，或`1.`）。
-在纯文本中标记顺序项目，这些项目应该结构为适当的列表。
-适当的列表标记允许屏幕阅读器宣布列表上下文（例如，“item 1 of 3”）。

# # # Emoji

-标记多个连续的表情符号，这对屏幕阅读器用户来说是破坏性的，因为每个表情符号的名称都是大声朗读的（例如，“火箭”“火花”“火”）。
-旗帜表情符号用于传达文本中无法传达的含义。
-表情符号应该谨慎使用。

# # 6。多媒体

-为录制的音频提供视频和文字说明。
—禁用自动播放音频和视频。
-建议在页面加载时暂停动画图像和其他动画。

# # 7。其他-链接：避免在新选项卡或窗口中打开链接。
粗体和斜体：屏幕阅读器通常不会显示粗体或斜体强调，所以关键信息不应该只依赖于这种样式。
—表：仅使用表存储数据。不要使用表格进行页面布局。避免嵌套表。避免使用复杂的表格，因为它们很难在标准Markdown中以可访问的格式表示。

##审查优先级

当存在多个问题时，按以下顺序排列优先级：

1. 图像上缺少或空的所有文本
2. 跳过标题级别或标题层次问题
3. 非描述性链接文本
4. 表情符号用作项目符号或列表标记
5. 简单的语言改进
6. 多媒体
7. 其他

##回顾语气-解释每个问题对可访问性的影响，指定哪些用户受到影响（例如，屏幕阅读器用户，认知障碍人士，非母语人士）。
-不要从写作中去除个性或声音。可访问性和吸引人的内容并不相互排斥。
保持建议的可操作性和针对性。
