# Symfony开发指南

遵循官方Symfony最佳实践和核心框架哲学开发Symfony应用程序的说明。

##项目背景
- Symfony（最新稳定版或LTS版）
—默认的Symfony目录结构
-启用自动装配和自动配置
-需要持久性时的ORM原则
-小树枝模板
- Symfony Forms, Validator, Security, Messenger
- PHPUnit用于测试
—支持基于属性的配置

项目结构
—使用默认的Symfony目录结构
-不要为应用程序代码创建bundle
-使用PHP名称空间组织应用程序代码
—配置保存在`config/`中，应用代码保存在`src/`中，模板保存在`templates/`中

# #配置环境配置
—使用环境变量进行基础设施相关的配置
—使用`.env`文件定义与环境相关的值
—不要使用环境变量来控制应用程序的行为

###敏感配置
-使用Symfony secrets存储秘密（API密钥，凭据）
—永远不要向存储库提交秘密

应用程序配置
—使用“`config/services.yaml`”中的参数配置应用行为
-仅在需要时覆盖每个环境的参数
—使用“`app.`”作为参数前缀，避免冲突
—使用简短的描述性参数名
-使用PHP常量配置值，很少改变服务和依赖注入
-只使用依赖注入
-首选构造函数注入
-默认使用自动布线和自动配置
-尽可能保持服务私密性
—避免通过`$container->get()`访问服务
—首选YAML格式进行服务配置
-使用可以改善解耦或清晰度的接口

# #控制器
—扩展`AbstractController`-保持控制器精简并专注于粘合代码
—不要将业务逻辑放在控制器中
—使用属性配置路由、缓存和安全
—对服务使用依赖注入
-在方便和适当的时候使用实体值解析器
-在需要时通过存储库显式执行复杂查询原则与坚持
-使用Doctrine实体作为普通PHP对象
-使用PHP属性定义Doctrine映射
—使用存储库查询数据
—避免将业务逻辑放在存储库中
—对所有模式更改使用迁移

模板（小枝）
—模板名、目录和变量使用snake_case
—用下划线作为模板片段的前缀
-让模板专注于呈现
避免在Twig模板中使用业务逻辑
—默认为转义输出
-避免使用`|raw`，除非内容是可信的和经过消毒的

# #形式
-将表单定义为PHP类
-不要直接在控制器中构建表单
-在模板中添加表单按钮，而不是在表单类中
-在底层对象上定义验证约束
-使用单个控制器动作来渲染和处理每个表单
—仅在需要多次提交时才在控制器中定义提交按钮# #验证
-使用Symfony验证器约束
-在应用程序边界验证数据
-当需要重用时，首选对象级验证而不是仅表单验证

# #国际化
-翻译文件使用XLIFF
-使用翻译键代替文字内容字符串
-使用描述键来表达目的，而不是位置

# #安全
—除非需要多个系统，否则最好使用单个防火墙
-使用自动密码散列器
—对复杂的授权逻辑使用投票者
—避免在属性中使用复杂的安全表达式

## Web资产
—使用AssetMapper管理web资产
-避免不必要的前端构建复杂性，除非需要

异步处理
—使用Symfony Messenger进行异步和后台任务
-保持消息处理程序小而集中
—为失败消息配置失败传输# #测试
-使用`WebTestCase`编写功能测试
-添加烟雾测试以确保所有公共url都能成功响应
—在功能测试中硬编码url，而不是生成路由
-在适合隔离逻辑的地方使用单元测试
-随着应用程序的发展，逐步添加更具体的测试

##一般指引
-更喜欢清晰而不是抽象
-在引入自定义模式之前遵循Symfony约定
—保持配置的清晰和可读
-避免过早优化
-使用Symfony Demo作为参考实现
