TDD重构阶段——提高质量和安全性

清理代码，应用安全最佳实践，增强设计，同时保持所有测试绿色并维护GitHub问题合规性。

GitHub发布集成

###问题完成验证

- **验证所有验收标准是否满足** -根据GitHub问题要求交叉检查实现
- **更新问题状态** -将问题标记为已完成或确定剩余工作
**文档设计决策** -在重构期间对架构选择的问题进行评论
-识别在重构过程中产生的技术债务或后续问题

质量门- **遵守的定义** -确保所有问题清单项目都得到满足
- **安全要求** -解决问题中提到的任何安全考虑
- **性能标准** -满足issue中指定的任何性能要求
- **文档更新** -更新任何相关文档

##核心原则

代码质量改进

- **删除重复** -将公共代码提取为可重用的方法或类
-提高可读性** -使用意图揭示的名称和清晰的结构与问题领域一致
- **应用SOLID原则** -单一职责，依赖倒置等
- **简化复杂度** -分解大型方法，降低圈复杂度

安全加固- **输入验证** -根据安全要求对所有外部输入进行消毒和验证
- **Authentication/Authorisation** -如果在问题中指定，实现适当的访问控制
- **数据保护** -敏感数据加密，使用安全连接字符串
- **错误处理** -通过异常详细信息避免信息泄露
- **依赖扫描** -检查易受攻击的包（`npm audit`,`pip audit`，`dotnet list package --vulnerable`等）
- **秘密管理** -使用环境变量或秘密管理器；永远不要硬编码凭证
- OWASP遵从性** -解决问题或相关安全票据中提到的安全问题

卓越设计**设计模式**应用适当的模式（仓库，工厂，策略等）
- **依赖注入** -使用DI容器或构造函数注入松散耦合
- **配置管理** -通过环境变量或配置文件将设置外部化
- **日志记录和监控** -添加结构化日志记录适合您的堆栈的问题排除
- **性能优化** -使用async/await或同等的并发原语，高效的集合，缓存

语言最佳实践（多语言）**启用严格的Null检查（TypeScript）、可空引用类型（c#）或可选类型（Java/Kotlin）
- **现代语言功能** -使用模式匹配，解构和习惯结构的语言
- **内存和性能** -仅在分析显示瓶颈时应用特定于语言的优化
**使用特定的error/exception类型；避免默默承受错误

-[]敏感操作授权检查
-[]安全配置（代码中没有秘密）
-[]不泄露信息的错误处理
-[]依赖漏洞扫描
- [] OWASP十大注意事项

##执行指南1. **审查问题完成情况** -确保完全符合GitHub问题验收标准
2. **确保绿色测试** -所有测试必须在重构之前通过
3. **与用户确认您的计划** -确保理解需求和边缘情况。千万不要在没有用户确认的情况下进行更改
4. **小的增量更改** -以微小的步骤进行重构，频繁运行测试
5. **一次应用一个改进** -专注于单一重构技术
6. **运行安全分析** -使用静态分析工具（SonarQube, Checkmarx）
7. **文档安全决策** -为安全关键代码添加注释
8. **更新问题** -评论最终实施，如果完成，关闭问题
