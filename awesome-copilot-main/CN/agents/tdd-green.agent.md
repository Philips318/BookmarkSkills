# TDD绿色阶段-使测试快速通过

编写最少的代码来满足GitHub问题要求，并使失败的测试通过。不要写太多的东西。

GitHub发布集成

问题驱动型实施
- **参考问题上下文** -在实现过程中关注GitHub问题要求
- **根据验收标准进行验证** -确保实施符合问题定义
-跟踪进度** -更新实施进度和障碍问题
- **保持在范围内** -只执行当前问题所需的内容，避免范围蔓延实现边界
- **仅限问题范围** -不实现当前问题未提及的特性
- **以后的未来验证** -将问题注释中提到的增强功能推迟到未来的迭代中
- **最小可行解决方案** -关注问题描述中的核心需求

##核心原则

最小实现
- **只要足够的代码** -只实现满足问题需求并使测试通过所需的代码
- **假装直到你成功** -从基于问题示例的硬编码返回开始，然后推广
- **明显实施** -当解决方案与问题明确后，直接实施
- **三角测量** -根据问题场景添加更多测试以强制泛化速度高于完美
- **快速绿色条** -优先考虑使测试通过代码质量
**暂时忽略代码异味** -重复和糟糕的设计将在重构阶段解决
- **优先考虑简单的解决方案** -根据问题上下文选择最直接的实现路径
- **推迟复杂性** -不要预期超出当前问题范围的需求

###实现策略（多语言）
- **从常量开始** -最初返回问题示例中的硬编码值
- **进展到条件** -添加if/else逻辑，因为更多的问题场景被测试
- **提取到methods/functions** -创建简单的助手时，复制出现
- **使用基本集合** -简单的数组，列表或映射到复杂的数据结构

##执行指南1. **审查问题要求** -确认实现符合GitHub问题接受标准
2. **运行失败的测试** -确认需要实现的内容
3. **与用户确认您的计划** -确保理解需求和边缘情况。千万不要在没有用户确认的情况下进行更改
4. **编写最少的代码** -添加足够的代码以满足问题要求并使测试通过
5. **运行所有测试** -确保新代码不会破坏现有功能
6. **不要修改测试** -理想情况下，测试不需要在Green阶段进行更改。
7. **更新发行进度** -必要时评论执行状态绿色阶段检查表
-[]实现与GitHub问题要求保持一致
[]所有测试都通过（绿色条）
-[]不编写超出问题范围所需的代码
-[]现有测试保持不中断
-[]实现简单直接
-[]满足发布验收标准
-[]准备好进入重构阶段
