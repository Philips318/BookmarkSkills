# Async编程最佳实践**命名：**所有异步方法以`Async`结尾（包括CLI处理程序）。
- **永远等待：**不要一火即弃；如果超时，**取消工作**
- **取消端到端：**接受`CancellationToken`，通过它，调用`ThrowIfCancellationRequested()`循环，使延迟可取消（`Task.Delay(ms, ct)`）。
- **超时：**使用链接`CancellationTokenSource`+`CancelAfter`（或`WhenAny`**和**取消挂起的任务）。
- **上下文：**在helper/library代码中使用`ConfigureAwait(false)`；省略在应用程序entry/UI.- **流JSON:**`GetAsync(..., ResponseHeadersRead)`→`ReadAsStreamAsync`→`JsonDocument.ParseAsync`；较大时避免使用`ReadAsStringAsync`。
- **取消退出代码：**返回非零（例如，`130`）。
- **`ValueTask`:**使用时只测量帮助；默认为`Task`。
- **异步处理：**优先选择`await using`异步资源；妥善保管streams/readers。
- **没有无意义的包装：**不要添加`async/await`，如果你只是返回任务。

#测试最佳实践##测试结构

-单独测试项目：**`[ProjectName].Tests`**。
—镜像类：`CatDoor`—>`CatDoorTests`。
—按行为命名测试：`WhenCatMeowsThenCatDoorOpens`。
-遵循现有的命名约定。
-使用**公共实例类；避免静态字段。
-没有branching/conditionals内部测试。

单元测试-每次测试一个行为；
-避免使用Unicode符号。
-遵循安排-行动-断言（AAA）模式
—使用明确的断言来验证测试名称所表达的结果
—避免在一个测试方法中使用多个断言。在这种情况下，最好使用多个测试。
当测试多个前提条件时，为每个前提条件编写一个测试
-当对一个前提条件测试多个结果时，使用参数化测试
-测试应该能够以任何顺序或并行运行
-避免磁盘I/O；如果需要，随机化路径，不要清理日志文件位置。
-通过**公共api **进行测试；不要改变能见度；避免`InternalsVisibleTo`。
-要求测试new/changed**公共api **。
-断言具体的值和边缘情况，而不是模糊的结果。
