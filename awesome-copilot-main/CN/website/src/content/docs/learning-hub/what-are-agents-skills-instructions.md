用GitHub Copilot建立良好的体验始于理解核心原语，这些原语塑造了Copilot在不同背景下的行为方式。本文阐明了每个工件的作用、如何将其打包到这个存储库中，以及何时使用它。

# #代理

代理是配置文件（`*.agent.md`），它描述：

-他们擅长的任务（例如，“地形专家”或“发射暗旗管理器”）。
—可以调用哪些工具或MCP服务器。
-可选的指导谈话风格或护栏的说明。

当你在VS Code中分配一个问题给副驾驶或打开**Agents**面板时，这些配置可以让你交换一个专门的助手。此回购中的每个代理都位于`agents/`下，并包含有关它所依赖的工具的元数据。在支持委托的产品中，主代理还可以启动临时的子代理来完成重点工作，如计划、研究或审查。参见[代理和子代理]（../agents-and-subagents/）了解协调模型。

什么时候去找代理

-你有一个从深度工具集成中受益的循环工作流程。
-您希望副驾驶主动执行命令或通过MCP获取上下文。
-你需要在整个编码过程中保持角色级别的护栏。
-你想要一个协调器，可以将更窄的工作委托给子代理。

# #技能

技能是自包含的文件夹，它为GitHub Copilot打包了可重用的功能。每个技能都位于自己的目录中，并包含一个`SKILL.md`文件以及可选的捆绑资产，如参考文档、模板和脚本。`SKILL.md`定义：-一个**名称**（在VS Code聊天和代理发现中用作`/command`）。
-一个描述，告诉座席和用户什么时候该技能是相关的。
-如何执行技能的详细说明。
-对技能所需的任何绑定资产的引用。

技能遵循开放的[代理技能规范](https://agentskills.io/home)，使它们可以跨GitHub Copilot以外的编码代理系统移植。

为什么技能比提示更重要

技能取代了早期的提示文件（`*.prompt.md`）模式，并提供了几个优点：- **代理发现**：技能包括扩展的前置事项，让代理发现和调用他们自动提示只能通过一个斜杠命令手动触发。
- **丰富的上下文**：技能可以将参考文件，脚本，模板和其他资产与他们的指令捆绑在一起，给AI更多的工作。
- **跨平台可移植性**：代理技能规范支持跨多个编码代理系统，因此您的投资与您一起旅行。
- **斜杠命令支持**：像提示符一样，技能仍然可以在VS Code聊天中通过`/command`调用。

何时获得技能-你想标准化Copilot对重复任务的响应方式。
-你需要捆绑资源（模板、模式、脚本）来完成任务。
—您希望代理自动发现并调用该功能。
-你喜欢引导谈话，但要有护栏和丰富的背景。

# #指令

指令（`*.instructions.md`）提供了Copilot在匹配文件时读取的背景上下文。它们通常包含：

-编码标准或风格指南（命名约定，测试策略）。
-特定于框架的提示(Angular最佳实践，。. NET分析器来抑制)。
-特定于存储库的规则（“永远不要提交秘密”，“功能标志必须存在于`flags/`”）。

指令位于`instructions/`下，可以使用全局模式对其进行全局作用域、每种语言或每个目录。它们可以帮助副驾驶自动与您的工程剧本保持一致。###何时寻求指导

-你需要持续的指导，适用于许多会议。
-您正在编写架构决策或遵从性需求。
-您希望副驾驶能够理解模式，而无需手动粘贴上下文。

工件如何协同工作

可以将这些工件视为互补层：

1. **说明**用长寿命的护栏奠定基础。
2. 技能让你可以根据需要触发丰富的、可重用的工作流，并让代理自动发现这些工作流。
3. **代理**带来最固执己见的行为，捆绑工具和指令到一个单一的角色。

通过结合这三者，团队可以实现：

-新开发人员的一致入职。
-可重复的操作任务，减少上下文切换。
-为专业领域（安全，基础设施，数据科学等）量身定制的经验。
