自动化是使GitHub Copilot应用程序每天都有用的最快方法之一。与手动要求Copilot重复执行相同的工作不同，您只需保存一次任务，然后按计划或按需运行它。

如果您不确定从哪里开始，请从模板开始，使其适应您的工作流程，并从实际运行中进行迭代。

从模板开始（然后自定义）

当您在Copilot应用程序中创建新的自动化时，请先浏览内置模板。它们为提示结构和范围提供了一个强有力的起点。

常见的例子包括：

- **对传入问题进行分类**（例如，将问题标记为`bug`，`enhancement`或`other`）
- **每晚修复失败的测试**（尝试修复并打开草稿拉取请求）
- **准备每周发布说明**（按时起草并打开拉取请求）即使这些都不是完全匹配的，模板也是避免空白页开始的最快方法。

使用工作表面审计技巧

发现有用的自动化的一个实际方法是让Copilot审核你的工作台面，并建议候选人。

如果你已经配置了MCP服务器（例如，Microsoft 365的WorkIQ或Slack MCP服务器），请先在常规聊天中尝试这样的提示：

>如果可用，使用WorkIQ （Teams/Outlook）和一个Slack MCP服务器来查看我最近的消息和日历。确定我缺少后续工作或重复工作的地方，并建议一个有用自动化的简短列表。

这通常会在一个过程中产生几个具体的自动化想法。然后将最好的一个转换为保存的自动化。

##在应用程序中创建第一个自动化1. 在Copilot应用侧边栏中打开**自动化**。
2. 单击**新建自动化**。
3. 从模板或从头开始。
4. 给它一个清晰的名字和一个具体的提示。
5. 选择何时运行（手动、每小时、每天或每周）。
6. 可选地设置模式、模型和推理工作。
7. 在第一次运行时使用**Create并运行**，这样您就可以立即检查输出并进行改进。

如果你的第一个版本只有70%的正确率，这很正常。最快的方法是从实际运行中进行迭代。

例子：Awesome Copilot每日PR总结

下面是在`github/awesome-copilot`存储库上使用的一个真正的应用内自动化：

|字段|值||---|---|
| **名称** |令人敬畏的副驾驶每日公关总结|
| **间隔** |每天09:00 |
| **模式** | |自动驾驶
|通过`gh api`打开pr，过滤过去24小时内的更新，并返回一个简明的汇总表|

为什么这很有效：

-范围很窄（一个回购，一个报告目标）。
—在提示符中有显式的命令示例。
-它以可预测的节奏运行，并产生易于审查的格式。

这是一个强大的启动模式，您可以将其复制用于问题分类、发布准备、审查跟踪或团队摘要。

在聊天中迭代以改善结果

每次运行之后，打开一个聊天窗口并直接优化自动化提示符。典型的改进:

-收紧范围（例如，只有特定的标签、团队或路径）
改进输出格式（表格，检查表，简短总结）
-添加明确的成功标准（包括或排除什么）这个目标并不是一个完美的第一个提示。目标是一个有用的自动化，每次运行都会变得更好。

来自社区的真实想法

团队已经在实际工作中使用循环自动化，例如：

-针对具体问题的每日状态更新
-审查和收件箱卫生任务
-经常性的个人工作流程维护

使用这些模式，然后根据自己的回购、仪式和沟通风格对其进行调整。

实用护栏

-保持提示明确，并限定在一个结果范围内。
-只赋予自动化所需的功能。
-避免提示中的秘密；在需要的地方使用存储库秘密和变量。
-更喜欢审查友好的输出，这样更容易信任和迭代。

##下一步打开**自动化**，选择一个模板，并将您当前手动执行的一个循环任务转换为每日运行。这一次的胜利通常会让下一个自动化变得显而易见。
