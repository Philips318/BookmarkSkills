# AI产品GTM

人工智能产品的市场进入策略。这些不是通用的AI原则——它们是将自主AI代理出售给企业的模式，在这些企业中，“自主”吓跑了买家，“队友”改变了他们。

##何时使用

* *触发:* *
“我们如何定位这个AI产品？”
“买家说他们担心人工智能会破坏生产”
-“我们应该叫它自动驾驶还是副驾驶？”
“当不同用户的使用情况相差10倍时，我们该如何给AI定价？”
-“企业安全通过了，但是ops拒绝了我们，为什么？”

* *背景:* *
- AI代理平台（编码，支持，运维）
—法学硕士类应用
-能够“做”事情的自主工具（而不仅仅是建议）
-人工智能基础设施
-任何由AI做出决定的地方

核心框架

# # # 1。真正的企业AI反对（不是你想的那样）

**销售自主AI代理的心得：**三个月过去了，企业安全审查很快就过去了。好兆头，对吧？然后模式出现了：安全批准了，但**操作拒绝了我们**。

反对意见不是“AI会破坏生产吗？”-他们“假设”它最终会破坏生产。真正的问题是：

**“如果代理做错了什么，谁来负责？”**

而不是“我们信任代理人吗？”“我们相信我们的团队能处理好这件事吗？”

**为什么重要：**

自主代理带来了新的操作负担。你不是在销售人工智能能力，而是在销售组织的准备程度。当你的经纪人在凌晨2点停止制作时，谁会收到传呼？谁来修理它？谁来向副总裁解释？

框架：问责级联**

在部署人工智能代理之前，企业需要明确的答案：1. **L1响应**：谁监控座席？（24/7运维团队，还是开发团队随叫随到？）
2. **L2升级**：当代理操作失败时，谁调试？（代理团队，还是产品团队？）
3. **L3所有权**：当出现严重故障时，谁拥有客户沟通权？

如果你不能回答这三个问题，他们就不会买。不管你的AI有多好。

**这将如何改变你的销售过程：**

* *老方法:* *
-演示AI
-显示精度指标
-谈论ROI

新方法:* * * *
-演示AI
—显式显示*故障模式*
-问：“你的团队中谁会处理这种情况？”
-了解他们的事件响应流程
-将AI失败映射到他们现有的运行手册

**资格问题：**

“请告诉我，当代理采取破坏工作流程的操作时会发生什么。谁会收到警报？调查谁?谁来决定是后退还是前进？”如果他们不能回答，说明他们还没准备好。暂停交易，先帮他们建立流程。

* *常见的错误:* *

将此视为“产品”异议（“我们将使AI更准确”）。这是一种“组织性”反对。更高的准确性并不能解决“谁在凌晨2点拥有这个？”

我见过的工作模式：**

在人工智能代理方面取得成功的公司已经有：
-生产系统的随叫随到
-事件响应剧本
-无可指责的死后文化
-清除升级路径

苦苦挣扎的公司：
—手动部署流程
英雄文化（“史蒂夫修复一切”）
-没有正式的事件响应
-以指责为中心的文化

* *决策标准:* *

在向企业展示自主人工智能之前，问问自己：“如果这破坏了他们的生产，那么他们的团队中谁拥有修复程序？”如果你不能回答，他们就不会买。

---# # # 2。副驾驶vs特工vs队友（三种不同的GTM动作）

**定位陷阱：**

早期的企业对话中，我们将其定位为“自主AI代理”。买家退缩。一个词的改变——“自主”→“AI队友”——会显著改善发牌进程。

为什么?**词语的选择会影响购买者的心理

**三个框架：**

* * 1。副驾驶（最安全，最低值）**
- **含义**:AI建议，人类每次都做决定
- **买家心理**：感觉安全，没有威胁
- **GTM运动**：开发者采用，自下而上
- **用例**：代码补全，写作辅助，搜索
**反对意见：“这值得花钱吗？”（感知价值低）* * 2。代理（最恐怖，最高值）**
- **含义**：人工智能自主行动，人类定期审查
- **买家心理**：可怕，意味着取代人类
- **GTM运动**：企业销售，自上而下
- **用例**：批处理，自动化工作流，运维
反对意见：“如果破坏生产怎么办？”(问责恐惧)

* * 3。队友（最佳位置）**
- **含义**：人工智能和人类合作，分工工作
- **买家心理**：合作，而不是替代
- **GTM动议**：混合（开发采用+经理批准）
- **用例**：大多数AI代理平台
- **反对意见**：“我们如何将其集成到我们的工作流程中？”(流程问题)

**定位移位：**

**以前：**“端到端处理复杂工作流的自主AI代理”
开发者：“很酷，但也很吓人”
经理：“这会取代我们的团队吗？”
-交易进程：缓慢**后：**“与你的工程师合作完成复杂任务的AI队友”
开发者：“这对我有帮助”
经理：“这让我的团队更有效率。”
-交易进展：三笔拖延了4个多月的企业交易在换班后的8周内完成

**重要的特定语言选择：**

❌**不要说：**
-“自主”（可怕）
-“替代”（威胁）
-“全自动”（无控制）
-“ai优先”（这到底是什么意思？）

✅**说：**
-“队友”（协作）
“增强”或“加速”（帮助，而不是替代）
-“一切由你掌控”（安慰）
-“处理重复性工作”（具体值）

**如何选择框架：**```
Does your AI make decisions without human approval?
├─ Yes → Are you selling to developers or enterprises?
│   ├─ Developers → "Agent" framing (they want autonomous)
│   └─ Enterprises → "Teammate" framing (they want control)
└─ No → "Copilot" framing (augmentation, not automation)
```
**残酷的事实：**

你可以建立一个代理，但把它定位为副驾驶。你不能造一个副驾驶然后把它定位为特工。**产品能力设定了一个上限，定位选择了你在这个上限以下的位置

* *常见的错误:* *

用“autonomous”是因为它听起来令人印象深刻。令人印象深刻≠值得信任。如果买家对你的定位望而却步，你就失去了他们。

# # # 3。AI定价问题（当使用量变化10倍时）

* *的模式:* *

我合作过的每一家人工智能公司都面临这样的问题：客户A使用1000个APIcalls/month.客户B使用10000个API。你们会多收顾客B 10倍的钱吗？如果是，它们会搅拌。如果没有，你的利润就会崩溃。

**三种模式：*** * 1。座位收费（每user/month$X）**
- **当它工作时**:AI可预测地增强人类的工作
- **示例**：代码补全，写作助手
- **问题**：不捕捉AI价值缩放
**真正的风险**：高使用率的客户是你最好的客户，但他们补贴了低使用率的客户

* * 2。基于使用（每个API呼叫/预测/小时$X）**
- **当它工作时**:AI做可变工作，客户理解单元
- **示例**：图像生成，转录，批量ML
- **问题**：高使用率客户的价格冲击
- **真正的风险**：客户优化使用*少*你的产品

* * 3。以结果为基础（每达成一个结果$X）**
- **当它有效时**：你可以可靠地衡量结果
- **示例**：“每个bug固定支付”或“每个支持票解决支付”
- **问题**：难以衡量，容易游戏
- **真正的风险**：你承担所有的风险，如果AI不执行**实际工作原理（混合）：**

基本费用（包括固定成本）+可变费用（按价值计算）。

* *例结构:* *
-基地：每队$X/month（可进入平台）
-变量：每成功action/outcome$Y
-为什么这样做：
-基地覆盖infra/support成本
-变量与客户价值一致
高使用率的用户不会受到惩罚（他们获得了更多的价值）

**我希望早点进行定价对话：**

基于使用情况的AI定价：

**问顾客：**
“手工做这个要花多少钱？”

如果每次API调用0.10美元，但节省了2美元的人工成本，那么你的定价就被低估了。如果每次通话花费0.50美元，但为他们节省0.40美元，他们就不会充分利用它。

* *定价规则:* *

你的可变成本应该是客户替代成本的20-30%。高到足以获取价值，低到足以让他们随意使用。

* *常见的错误:* *复制OpenAI的定价（每1000个代币0.01美元），因为“每个人都这么做”。你的成本结构不是OpenAI的成本结构。你的价值不是OpenAI的价值。你的生意价格。

# # # 4。AI信任阶梯（来自攀登者）

* *的模式:* *

你不能通过说“相信我们，它有效”来推销人工智能。你要分阶段建立信任。

**第一：透明度（第一次演示之前）**

在他们问之前发送这三个文档：
-模型卡（什么模型，受过什么训练，在什么基准上的准确性）
-安全白皮书（数据流向何处，如何处理）
-可解释性文档（如何解释AI决策）

**工作原理：**
买家希望尽职尽责。如果你在医生要求之前就把他们送过去，你会显得自信可信。

**第二：控制（在演示中）**向他们展示安全机制：
-用户如何approve/rejectAI建议
—Kill开关和回滚机制
-自信分数和当AI说“我不确定”时

**工作原理：**
对“失控的人工智能”的恐惧是真实存在的。展示控制机制证明你考虑过故障模式。

**第三：演出（第4-8周）**

证明它是有效的：
-基准vs基线（人工或以前的工具）
-类似公司的案例分析
-实时演示他们的数据（如果可能）

**工作原理：**
事实胜于承诺。一个顾客说“我们节省了Xhours/week”相当于100个营销宣传。

**第四：规模（当他们认真的时候）**

显示企业准备就绪：
—企业部署示例
-大规模性能（延迟、吞吐量、错误率）
-合规文件（SOC 2、GDPR等）

**工作原理：**
企业不会部署mvp。他们需要证明你不会因为1000个用户而倒下。

**我犯的错误：**在解释AI如何工作之前，先证明它的性能。买家不相信基准，因为他们不了解这个系统。* *问题。* *

* *决策标准:* *

如果买家在你演示之前问“这是如何工作的”，你就跳过了透明度。备份，把医生送来。

# # # 5。企业AI演示（展示失败，而不仅仅是成功）

**什么不工作：**

AI可以神奇地解决所有问题的演示。买家认为“这对我们混乱的数据不起作用。”

* *工程:* *

显示AI犯了一个错误，然后恢复过来。认真对待。

**工作的演示结构：**

* * 1。问题（30秒）
“你的工程师在（特定任务）上花费数小时。这就是它的样子。”
—显示：当前手工工作流程
-量化：时间×工程师×周=总成本* * 2。AI尝试（60秒）**
“这是人工智能处理同样的任务。”
-显示：AI分析，采取行动
- **键移动**：让AI遇到错误或不确定性
-显示：AI重新分析，恢复，或寻求帮助
- **旁白：“注意，它第一次没有做到完美。它像人类一样处理不确定性。”

* * 3。人类评论（30秒）**
“这是工程师审核和批准的地方。”
-展示：工程师检查AI的工作
- **键移动**：显示工程师覆盖或调整某些东西
- **旁白**：“人类仍在掌控之中。人工智能处理重复性工作，人类处理判断。”

* * 4。结果（30秒）**
“[X小时]→[Y分钟]。工程师仍然拥有结果，人工智能加速了执行。”
-量化：减少时间，节约成本，释放产能

**为何有效：**-显示失败→建立信任（你没有隐瞒任何事情）
-显示恢复→证明AI是健壮的
-显示人类覆盖→给他们控制
-量化节省→使ROI具体化

**我见过的模式：**

完美AI演示→买家怀疑
带有不完美AI的演示可以恢复→买家参与

* *常见的错误:* *

挑选人工智能100%准确的例子。买家知道真实世界的数据是混乱的。如果你不表现出凌乱，他们会认为你在隐藏。

# # # 6。“谁拥有这个？”异议处理程序

反对* *:* *

“这看起来很棒，但如果AI做错了怎么办？”

* *坏的答案:* *
“我们的人工智能准确率达到95%，而且我们每周都在改进。”
（换句话说：“它会有5%的时间导致生产中断，祝你好运。”）

* *好的答案:* *
“伟大的问题。让我们一起经历一个失败的场景。”

* *然后问:* *1. “当人工智能采取导致错误的行动时，你的团队中谁会去调查？”
2. “你们有针对工具故障的事件响应流程吗？”
3. “谁拥有回滚的决定权——是批准它的工程师，还是运维团队？”

**它的作用：**

-从“它会失败吗？”（是的，它会）到“我们如何处理失败？”
-让他们通过行动准备来思考
-显示他们是否准备好了AI代理

* *后续:* *

“我们的建议是：从低风险的环境开始。让AI处理非关键工作流程2-4周。看看你的团队是如何处理错误的。当你对这个过程有信心时，再扩大范围。”

**为何有效：**

你不是在推销完美。您正在销售一个需要操作成熟度的工具。**筛选成熟买家比说服不成熟买家更好

* *的模式:* *成熟的买家说：“我们已经有了工具故障的运行手册，我们将在其中添加人工智能。”
不成熟的买家说：“你能让它永不失败吗？”

* *决策标准:* *

如果买家要求100%准确，那就走开。他们还没准备好。当他们有事件响应过程时再回来。

# # # 7。AI定位陷阱（对抗非对称战争）

* *的模式:* *

你是在人工智能代理领域竞争。每个竞争对手的主页上都写着同样的话：“用人工智能自动化（工作流）。”你的差异化需要解释买家不理解的复杂技术基准。

这就是定位陷阱：在自己的战场上与资金更雄厚的公司在功能上竞争

如何诊断：**1. 收集5-7个直接竞争对手的主页信息
2. 确定共同的主张（这些都是商品化的——你在这里赢不了）
3. 绘制出你有结构优势的地方（不仅仅是产品特性）
4. 找到竞争对手无法轻易复制的位置

** AI定位的结构性优势：**
-独特的数据或工作流所有权（你可以控制竞争对手无法复制的东西）
-部署灵活性（内部部署、私有云、客户控制的基础设施）
-定价模式创新（以结果为基础，当竞争对手以座位为基础时以使用为基础）
-社区或生态系统（随着时间的推移而复合的网络效应）

不会持久的功能优势：
“更好的准确性”（竞争者在一次冲刺中赶上）
“更快的推理”（基础设施商品）
-“更多集成”（容易复制）

测试:* * * *对于每一个定位要求，都要问一问：竞争对手能否通过单一的产品冲刺来复制这一点？如果是，那就站不住脚了。不要在此基础上构建您的GTM。

* *常见的错误:* *

声称自己比别人“更擅长”。在人工智能领域，基准每月都会变化。关注你的方法在结构上的不同，而不是你的模型暂时更好的地方。

# # # 8。天花板时刻资格（寻找高意向AI买家）

* *的模式:* *

对人工智能代理意向最高的企业买家是那些已经采用了类似工具并达到极限的人。他们在学习上有所投入，他们了解问题空间，他们对升级有清晰的商业案例。

**如何识别天花板时刻：**前景有：
-使用copilot/assistant工具6个月以上
-达到了它的局限性（不能处理复杂的任务，不能和他们的堆栈一起工作，不够自主）
-低转换成本（心智模型转移）
清晰的商业案例（“即使使用当前的工具，我们也要花X个小时手动完成”）

**如何瞄准他们：**

1. 确定你的人工智能产品补充或取代的工具
2. 构建已知使用这些工具的公司的目标列表
3. 围绕局限而非功能进行拓展：
-“当团队需要你的产品提供的功能时，他们经常会遇到瓶颈。”
承认现任者的价值（不要说废话）
-定位为“下一个层次”，而不是替代

**为什么这个转换更好：**天花板时刻的对话比冷接触转换3-5倍，因为：
-前景已经了解问题所在
-他们已经在这个领域投资了
-他们有内部预算分配
-他们能清楚地表达出缺失的东西

**资格问题：**

“你尝试用现有工具自动化的最复杂的任务是什么？它在哪里失败了？”

如果他们有一个特定的答案和特定的痛苦，他们就是天花板时刻的买家。如果他们说“很好”，那他们还没准备好。

* *常见的错误:* *

试图说服不懂工具的潜在客户采用人工智能代理。糟糕的转化率，漫长的教育周期，他们会把你比作“什么都不做”，而不是“做得更好”。目标是已经相信这个类别的买家。

决策树

我应该使用哪个定位？```
Does your AI act autonomously (no approval per action)?
├─ Yes → Who are you selling to?
│   ├─ Developers → "Agent" framing
│   └─ Enterprises → "Teammate" framing
└─ No → "Copilot" framing
```
我应该使用哪种定价模式？```
Can you measure customer outcomes reliably?
├─ Yes → Outcome-based (or hybrid with outcome component)
└─ No → Continue...
    │
    Does usage vary 5x+ by customer?
    ├─ Yes → Hybrid (base + usage)
    └─ No → Seat-based
```
这个买家准备好接受人工智能代理了吗？```
Do they have incident response processes for tool failures?
├─ Yes → Continue...
│   │
│   Do they have on-call rotations for production systems?
│   ├─ Yes → Qualified buyer
│   └─ No → Help them build it first
└─ No → Not ready (come back in 6 months)
```

常见错误

* * 1。使用“autonomous”是因为它听起来令人印象深刻
-我看到过缓慢的交易。“自主”吓坏了企业。“队友”进展更快。

* * 2。隐藏AI失败模式**
买家知道真实世界的数据是混乱的。如果你不展示失败，他们会认为你在隐藏失败。

* * 3。以“会影响生产吗？”作为反对意见**
-真正的反对意见：“当它发生时谁负责？”组织准备，而不是准确性。

* * 4。基于使用的AI定价，如OpenAI**
-你的成本结构不是他们的。价格为客户替代成本的20-30%。

* * 5。在演示之前跳过透明度文档
——秩序很重要。透明度→控制→性能→规模。不要跳过步骤。

* * 6。演示完美的AI**
-显示错误+恢复。比虚假的完美更能建立信任。* * 7。销售给要求100%准确性的买家**
-他们还没准备好过滤成熟的买家与事件响应过程。
