# 0比1发射

推出新产品，从想法到第一批客户。目标不是上头条，而是找到10个离不开你的客户。

##何时使用

* *触发:* *
-“我们如何推出这个产品？”
-“第一客户获取策略”
“我们发布了，但是没人用”
-“产品搜索vs直接推广？”
-“我们有意识，但没有皈依”
-“我怎么知道这是否有效？”

* *背景:* *
-新产品发布
-功能发布感觉像新产品
-找到前10-50个客户
-验证产品与市场的契合度
-诊断早期牵引力停止的原因

---

核心框架

# # # 1。新闻≠增长（获得12个注册用户的发布）

* *的模式:* *

协调功能发布和媒体巡回宣传。TechCrunch, VentureBeat，产品博客。重大公告日。

* *结果:* *
- 5万印象
- 12个注册
- 2次转换

**失败原因优化媒体嗡嗡声，而不是用户价值。该功能还不适合自助服务。它需要教育、背景和指导。媒体会吸引你的眼球。但是没有激活的眼球=虚荣。

**什么更有效：**

直接给50个目标客户发邮件。“我们之所以创建（功能），是因为像你们这样的团队正在努力解决（问题）。想要抢先体验？”亲自引导他们完成设置。获取反馈，迭代。

**结果：** 50封邮件→15封回复（30%回复率）→8次试用→4次转化（50%试用付费）。

* *教训:* *

早期客户来自于直接宣传，而不是新闻报道。新闻稍后再处理（A轮公告，重大里程碑）。对于0比1，这是分散注意力。

# # # 2。三层诊断（为什么启动失速）

* *的模式:* *你启动。你有一些意识。但转化率很低。问题存在于三个层次中的一个，每个层次都需要不同的干预。

**第一层：定位问题**

症状:
-短信听起来像竞争对手
-差异化需要解释复杂的技术细节
-买家认为你是可以替代的
-销售对话被比较问题搞得一团糟

诊断：你“在错误的战线上打一场不对称的战争”——在功能上与资金更雄厚的公司竞争。地图上竞争者声称独特价值的地方。找到他们无法轻易复制的位置。

解决办法：在结构上（而不仅仅是通过产品功能）提出自己的主张。在提交产品资源之前使用出站消息传递进行测试。

**第二层：经验问题**症状:
-意识强但激活弱
-用户注册，但没有完成第一个工作流
-多个入口点导致决策瘫痪
文档以功能为中心，而不是以结果为中心

诊断：没有预设值的灵活性是一种负担，而不是特性。用户面临着“选择悖论”——太多的选择，却没有足够的指导来让他们顿悟。

解决办法：确定2-3个“不可否认的用例”，提供即时价值。限制入职到那些特定的用例。在精通路径后面添加高级功能。围绕要完成的工作重写帮助内容，而不是功能列表。

**第三层：对齐问题**

症状:
-团队报告客户“带宽不足
-不同的功能针对不同的指标进行优化
-每个想法都有同等的重要性（没有决胜局）
-没有明确的北极星将活动与结果联系起来诊断：“探索模式”——每一项举措都具有同等的优先级——在资源受限时变得具有破坏性。

修正：定义一个单一的共享北极星。在做每一个决定时都把它当作决定性因素：“这能帮我们赢得客户吗？”减少那些不能提升的活动。每周，而不是每季度都要看到进步。

**使用方法：**

当发射停止时，在投入资源之前诊断出哪一层损坏了。当问题是定位时修复经验会浪费工程时间。当问题是内部一致性时，修复定位会浪费营销支出。

# # # 3。前10个客户框架

**原则：**前10个客户不是为了盈利。它们是用来学习的。**你在学习什么：**
1. 这个产品真的能解决问题吗？
2. 激活流是什么？（它们如何获得价值？）
3. 有什么反对意见吗？（价格、功能、集成？）
4. 谁是真正的买家？（头衔、角色、预算权限？）
5. 销售周期是怎样的？（几天、几周、几个月？）

**如何找到他们：**

**渠道1：个人网络（前2-3）**
“我在做X，你能给我一些反馈吗？”
-转化为付费用户（不要免费赠送——免费用户的反馈与付费用户不同）

**渠道二：直接外联（客户3-20）**
-建立100个目标帐户的列表
-针对他们的具体痛苦进行个性化处理
-测试消息变体-哪个角度得到回复？通道3：天花板时刻目标（最高意图）**
-意向最高的潜在客户是那些已经采用类似解决方案并达到极限的人
-他们已经投资学习一种工具，达到了上限，并且转换成本很低
-围绕局限性进行拓展：“我们看到，当团队需要（能力）时，他们的能力已经超出了现有团队的能力。这就是我们所创造的。”
-这些人的转化率比冷宣传高3-5倍，因为他们已经了解问题所在

**渠道四：社区（开发者产品）**
“构建[X]来解决[问题]，寻找早期用户”
-提供白手套入职
-最适合用户聚集在Slack/Discord/forums的产品

# # # 4。2周实验周期

* *的模式:* *

早期阶段的速度比完美更重要。限制不是你是否正确，而是你测试假设和迭代的速度有多快。

**如何执行：**-在开始之前，为每个测试制定明确的成功标准
-每个实验测试一个变量（消息，渠道，价格，功能）
-最多运行2周-如果到那时还没有显示信号，它就不会
—如果成功，一周内分配3倍的资源
-如果它没有，杀死它并移动到下一个测试
不管结果如何，记录下你所学到的东西

**剧本规则：**

每一个成功的实验在扩大规模之前都必须成为一个剧本。结构：目标→步骤→预期产出→指标→风险。如果一个不熟悉的人不能执行剧本，说明它没有被充分地记录下来。

**为什么重要：**

一次性的胜利不会复合。系统化的实验可以。目标不是一次发射，而是建立一个可重复的机器来快速测试假设。

* *常见的错误:* *测试前的过度计划。在发射前等待“完美”的条件。在失败的实验中停留太久是因为你投入了情感能量。根据70%的信息做出决定。

# # # 5。合作伙伴主导的市场进入（当你没有分销渠道时）

* *的模式:* *

与其仅仅通过直接销售进入新市场，不如利用与老牌企业的合作来加速。

**如何执行：**1. 确定目标细分市场的市场领导者
2. 解决客户问题，而不是合作伙伴关系——“如果你的用户可以访问[功能]怎么办？”从你的需求转移到他们的需求
3. 从小事做起：帮助他们解决一个具体问题（狭隘的整合，而不是全面的合作）
4. 在要求更广泛的承诺之前，先用3-6个月的试点来证明价值
5. 共同建立参考客户-降低他们的风险
6. 利用他们的GTM：一旦整合，他们就会向他们的基础营销

**超级节点模式：**

将自己定位为其他工具自然连接的集成中心。您拥有其他平台需要的关键数据或工作流。这是复合的——每一个新的伴侣都会让你对下一个更有价值。

* *类别排序:* *不要到处追求伙伴关系。每个季度主导2-3个类别：
1. 以真实的用例为导向：“我们的用户每月要求[合作伙伴]集成50次”
2. 一旦你与顶级玩家合作，竞争对手也会感到迫切需要与你合作
3. 在一个类别中建立2-3个成功的合作伙伴关系后，创建共同的客户故事

* *常见的错误:* *

在没有明确整合途径的情况下启动伙伴关系。期望合作伙伴在没有支持的情况下提高意识。将合作伙伴关系视为销售渠道，而不是平台扩张。

# # # 6。PMF验证检查表

**产品与市场的契合是客户推动你前进，而不是你推动他们前进

* *保留:* *
-[] 40%以上的第1周用户在第4周返回
-[]使用率随时间增加
-[]客户在没有销售推动的情况下续签有机增长:* * * *
-[]口碑推荐正在发生
-[]客户询问“我可以添加我的团队吗？”
-[]没有付费营销的入站利息

* *销售速度:* *
-[]销售周期缩短
-[]胜率>30%的试验
-[]顾客说“我们现在需要这个”

定性:* * * *
-[] 40%如果产品消失了，我非常失望（Sean Ellis测试）
-[]客户可以清楚地表达它的用途（清晰的用例）
-[]客户公开倡导

**如果你没有这些，你还没有PMF。不要缩放marketing/sales.**

决策树

为什么我们的发行会停滞？```
Do prospects understand what you are?
├─ No → Layer 1: Positioning problem
│         Fix: Test new messaging before changing product
└─ Yes → Continue...
    │
    Do users activate after signing up?
    ├─ No → Layer 2: Experience problem
    │         Fix: Restrict onboarding to 2-3 use cases, guide to aha moment
    └─ Yes → Continue...
        │
        Is the team aligned on what matters?
        ├─ No → Layer 3: Alignment problem
        │         Fix: Single north star, weekly visibility, cut non-essential
        └─ Yes → Keep iterating, you're on the right track
```
媒体发布还是直接推广？```
Self-serve ready? (Users get value in <10 min)
├─ No → Direct outreach only (press won't convert)
└─ Yes → Do you have >$1M funding to announce?
    ├─ Yes → Both (press for awareness, outreach for conversion)
    └─ No → Direct outreach first, press later
```

常见错误

* * 1。优化标题而不是激活**
5万印象和12个注册用户。新闻≠增长。

* * 2。上线前没有目标客户名单**
在0比1的情况下，喷雾和祈祷是行不通的。首先建立100个帐户的列表。

* * 3。没有默认值的灵活性**
给用户提供所有选择只会麻痹他们。选择2-3个不可否认的用例并努力指导。

* * 4。免费赠送产品**
免费用户给出礼貌的反馈。付费用户会给出诚实的反馈。

* * 5。学习**前的缩放
前10个客户是为了学习，而不是为了收入。记录一切。

* * 6。计划,正在测试* *
2周实验，有明确的杀伤标准。快速行动，记录学习。

* * 7。诊断错误的层**
当问题是体验时定位修复=浪费营销。当问题是定位时，经验修正=浪费工程。
