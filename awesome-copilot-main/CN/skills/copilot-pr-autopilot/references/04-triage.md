# #过程

对于每个线程，按顺序应用此文件中的标题：

1. **查看器类型策略** -`human-or-bot`线程默认为`escalate-to-user`，除非用户明确地限定了它们的作用域。
2. **ROI vs风险** -对`copilot`线程进行评分和决定。
3. 修复/拒绝规则列表** -匹配查找模式。
4. **项目特定的策略挂钩** -研究报告约定
在应用通用“修复”之前。
5. **冲突-评论解决** -如果发现翻转a

6. **升级规则** -升级设计级权衡；large/cross-cutting变化，或high-risk/irreversible动作。每个线程返回`{ thread_id, action, rationale }`给父线程；
步骤5只消耗`fix`行，步骤8消耗整个表。

# #陷阱

- **每个子代理调用不超过5个的批处理。**大批量生产
模糊基本原理，超出5分钟的预算。
- **人类/高级安全默认为`escalate-to-user`.**
自动回复或自动解决人工审查线程隐藏
未解决的问题和社会错误。
- **引用`rationale`**中的规则-一行，具体。
“风格单位标题§衰落”很好；“看起来很小”不是。
- **振荡硬停止是不可协商的。**如果座席是
即将进行编辑它已经在前一轮中恢复了，这是
振荡回路的明确特征-升级。

#分类分类决定是否修复或拒绝每一个副驾驶的发现。
我们的目标是正确，而不是绥靖——什么时候自信地拒绝

投资回报率vs风险

在两个轴上对每个提议的变化进行评分，然后决定：

**ROI** =修复的价值减去实施的成本减去
用户审查的成本。
**风险** =爆炸半径，可逆性，对不相关代码的影响。

|投资回报率|风险|行动||---|---|---|
|清除正|低|单边修正。|
|边际|低|修正如果便宜；否则就有理由下跌。|
|清除正向|高/不可逆|优先向用户建议。|
|边际|高|下降。|
|负（假设的过度工程）|任何|下降。|

##当发现是…-一个纯粹假设的种族，需要跨阶层的管道，
实际的暴露是可以忽略不计的。引用交错的你
排除。
- **样式、命名或格式化**。超出了审查循环的范围。
- **添加抽象的建议**(“引入策略模式”，
“提取一个接口”)，而不是为自己买单
代码库的当前规模。
- **与既定项目惯例相矛盾的建议** -
与周围代码的一致性通常比代码的一致性更有价值
孤立的建议。
- **微优化**的代码，不是在热路径上。

特定于项目的策略挂钩有些结果是由项目政策决定的，而不是由总体决定的
推理的正确性。在应用通用的“修复”之前，**研究
首先是回购自己的约定** -`.github/instructions/*.md`文件通常有一个`applyTo`全局变量，用于将它们固定到已更改的文件
文件路径),`.github/skills/`,`AGENTS.md`,`CONTRIBUTING.md`， CI
配置，以及最近提交到类似文件的文件。扇开倍数`explore`子代理当几个轴需要检查时(lint, format，
拼写检查，许可证头，等等)-不要发明答案。什么
看起来很明显的修复可能会违反项目规则：- **拼写检查/字典发现。**如果项目使用
拼写检查器（`check-spelling`,`cspell`,`typos`，或类似）；
检查它的配置和最近的提交来了解本地的
约定(重新定义文档，添加pattern/regex，扩展adictionary/allowlist，使用内联忽略)。遵循这个
公约;不要发明新机制。
**Lint抑制/内联忽略指令。**大多数项目
需要一个内联的基本原理注释。赤裸裸的压制得到了推进
回来。
- **许可证头文件/文件样板。**项目特定格式；
通常是ci强制-从相邻文件复制现有的头文件。
- **测试框架，模拟库，格式选择。**遵循

在回复中引用项目的配置文件或约定。

相互冲突的评论-提前打破振荡失败模式：第N轮“修复”评论A要求的内容；圆的N + 1
注释B对象并要求还原它。盲目的善变

解决规则-按顺序应用，在第一个触发时停止：

1. **从原则中重新推导。**选择在比赛中获胜的一方
函数契约+周围模式+用户声明
偏好——不是最新的评论。
2. **更喜欢有明确理由的立场。* *混凝土
失败模式（安全性、正确性、数据丢失、性能）胜出
风格上的位置。
3. **更喜欢人类的评论，而不是机器人的评论**当他们直接
冲突。
4. **如果仍然模棱两可，向用户升级。**两者总结
与推荐并列的位置；不要默不作声
选择。**硬停止**：如果你要做同样的编辑你
在之前的回合中，停止并升级。这就是
振荡环的无二义特征。

##回复卫生

每一个答复——修正或拒绝——都说明了理由。这使得
PR自文档化，并为下一次审查提供可见的上下文。
拒绝的调查结果引用了前一轮，并解释了为什么存在
形式是正确的，所以下一个审稿人不会再提出它。

##升级规则

默认保持自动驾驶；在以下情况下升级到用户：

-该发现确定了与多个设计级的权衡
合理的解决方案，没有明确的赢家。
-修复将**大或横切**（数百行），
新的架构，跨模块重构)。
-动作**高风险或不可逆**(强制推送、删除、
凭证、生产)。

否则，决定并继续。
