#步骤5：应用修复

子代理类型：`general-purpose`， **每次发现一个子代理**，
并行**最多5个并发**；预算：每人5分钟。如果步骤4返回
超过5行`fix`行，父进程以≤5的波运行第5步。

# #输入

每个子代理（每次调用一个发现）：
-步骤3中的`thread_id`，`file`,`line`。
-发现`summary`和副驾驶的建议修复（如果有的话）
-第4步的分类`rationale`-代理已经决定了
是`fix`；这个子代理只实现它。

##返回合同```
{ thread_id, files_touched, summary, status }
```
`status`∈`complete`|`partial`|`blocked`和`summary`是什么
对更改的一行描述。

# #过程

1. **发现正在编辑的区域的repo约定-首先
在编写任何代码之前，请阅读：
-`.github/instructions/*.md`，其`applyTo`全局变量匹配     file's path,
——`.github/skills/`——`AGENTS.md`——`CONTRIBUTING.md`-邻接文件模式在同一目录和最近提交     touching similar files.
2. 按照这些约定应用修复。
3. 返回`files_touched`+一行`summary`+`status`。

# #陷阱**最多5个并发修复子代理。**帽防止固定扇出
混乱;父进程合并结果并协调文件冲突
步骤6之前的波浪之间。
- **永远不要发明一个与回购实践相矛盾的通用答案
这就是“学校里的大象”的反模式——副驾驶的建议
孤立地看起来是正确的，但破坏了项目的lint，格式，
拼写检查、许可头或框架约定。这个
发现步骤是强制性的，而不是可选的。
- **每个子探员一个发现。**修复需要触摸相同的
文件在wave之间被父文件序列化-不要合并
将多个发现结果放入一个子代理调用中。
- **项目政策胜过副驾驶建议。**如果发现浮出水面
一个文档化的约定（拼写检查允许列表机制）
抑制样式等)与建议的修复相矛盾，请遵循
惯例和反映，在回复主体在步骤8中起草
(见[04-triage.md] (04-triage.md# project-specific-policy-hooks))。
- **如果实施修复将会以书面理由推回
过度设计一个假设的边缘情况-翻转
分类到`decline`，并返回`status: blocked`和基本原理
因此，步骤8起草正确的答复。
