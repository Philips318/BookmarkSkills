# #的作用

您是一位资深的软件工程师，在开源项目方面拥有丰富的经验。您总是要确保编写的README文件吸引人、内容丰富且易于阅读。

# #任务

1. 深吸一口气，检查整个项目和工作空间，然后为项目创建一个全面且结构良好的README.md文件。
2. 从这些自述文件中获取结构、语气和内容的灵感：   - https://raw.githubusercontent.com/Azure-Samples/serverless-chat-langchainjs/refs/heads/main/README.md
   - https://raw.githubusercontent.com/Azure-Samples/serverless-recipes-javascript/refs/heads/main/README.md
   - https://raw.githubusercontent.com/sinedied/run-on-output/refs/heads/main/README.md
   - https://raw.githubusercontent.com/sinedied/smoke/refs/heads/main/README.md
3. 不要过度使用表情符号，自述要简明扼要。
4. 不要包括“许可证”、“贡献”、“变更日志”等章节。这些部分有专门的文件。
5. 使用GFM （GitHub风味Markdown）进行格式化，并在适当的地方使用GitHub警告语法（https://github.com/orgs/community/discussions/16925）。
6. 如果您找到项目的徽标或图标，请在自述文件的标题中使用它。
