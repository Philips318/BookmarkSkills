#产品主导型增长

建立自助式获取和扩展活动。但首先，要弄清楚PLG是否适合你的产品。

##何时使用

* *触发:* *
-“我们应该建立PLG还是销售主导？”
-“我们如何推动自助服务的采用？”
“免费模式到付费模式的转换行不通”
-“开发者主导的采用策略”
-“我们应该投资哪些增长渠道？”
我怎么知道PLG能不能起作用？

* *背景:* *
-开发人员工具和平台
-具有自助服务潜力的B2B SaaS
-产品的价值是显而易见的，没有演示
-自下而上的采用动议
——优先考虑增长渠道

---

核心框架

# # # 1。PLG现实检查（提交前测试）

**我学到的两个动作并行运行：**经典的创业辩论。PLG阵营：“开发者想要自助服务。”销售阵营：“企业需要手把手。”我们没有争论，而是分别测试了6个月。同样的产品，两次GTM移动，追踪到了一切。

* *结果:* *

PLG：高销量，低ACV（约5000美元），快速创收，高流失率。以销售为主导：较低的销量，较高的ACV（约5万美元），较慢的盈利时间，较低的流失率。虽然销售量减少了1 / 10，但销售额却增加了1 / 10

**原因：**产品复杂性+买家资历=以销售为主导的胜利。该产品需要与现有的基础设施集成，跨团队的变更管理，以及多涉众的一致性。开发者喜欢自助服务。但他们不是经济买家。

**PLG工作时：**
—价值在前5分钟很明显
-实现是微不足道的
-个人用户在没有团队支持的情况下获得价值
—没有procurement/legal栏
-买方=用户**销售主导在以下情况下有效
—产品要求integration/setup-多个利益相关者需要协调一致
-买方≠用户
-交易规模证明人性化是合理的
-客户需要教育才能看到价值

**在构建PLG之前，测试你的运动。不要因为PLG很流行就认为它更好。** PLG在数量上是有效的，但以销售为主导的复杂性可能更有利可图。

# # # 2。增长方程（将投入映射到产出）

* *的模式:* *

当你系统化活动和用户获取之间的关系时，增长就会变得复杂。不是“做更多的营销”，而是将具体的投入映射到可衡量的产出。

**如何建立你的增长方程式：**

对于每个通道，定义：活动（输入）→流量（输出）→转换。- **有机搜索：** 1篇优质博客→400users/month→5%转化率= 20个新用户
**付费广告：**花费1000美元获得8%的转化率，获得10万次印象= 8K点击→X%的转化率
- **社区活动：** 1个活动→60个参与者→35%转化率= 21个用户
- **推荐：** 1个整合合作伙伴→N个推荐用户→Y%的转化率

**为什么重要：**

一旦你验证了这个等式，缩放就变成了数学。“我下个月需要200多名用户”→“我需要10多篇博客文章”或“我需要5000多美元的广告支出”。没有方程，你只能猜。

**测试等式：**

1. 从假设开始：“如果我创造X，它就会推动Y转换”
2. 用小样本测试：1篇博客文章，测量实际转化率
3. 验证：现实与假设相符吗？
4. 有信心地扩大规模：如果是，增加投入
5. 如果不行就杀了：4周的数据就足够决定了

* *常见的错误:* *不经过测试就猜测转换率。假设来自同一频道的所有用户质量相同。在验证方程之前进行缩放。

# # # 3。频道经济（杀死失败者，加倍下注赢家）

* *的模式:* *

每个频道都有经济因素。如果不跟踪它们，你就会在失败者身上过度投资，而在成功者身上投资不足。

**轨道每通道：**
1. **CAC:**总支出/新用户
2. **转化率：**注册→付费
3. **保留时间：**按来源划分为30天、90天
4. **LTV:**按渠道划分的客户生命周期收益
5. **投资回收期：**多久可以收回CAC

**决策框架：**

- CAC < （LTV ×保证金）→大举扩张
- CAC≈（LTV ×保证金）→优化，不要缩放
- CAC > （LTV ×保证金）→4周内杀死

**每月渠道回顾：**哪些渠道是盈利的？哪些是排水沟？季度重新分配：3倍的预算给赢家，杀死输家。**关键洞察：渠道质量变化**

便宜的CAC并不意味着好的CAC。自然搜索可能以0美元的CAC为用户提供85%的30天留存率。付费搜索可能以12美元的CAC为用户提供45%的30天留存率。当你考虑到留存率和LTV时，“免费”渠道的价值要高出10倍。

* *系统测试:* *

每月测试2个新频道。给每个4周的数据。如果经济不起作用，果断杀人。不管结果如何，都要记录学习成果——失败的东西和成功的东西一样有价值。

* *常见的错误:* *

无保留跟踪CAC。流失用户的廉价渠道比留住用户的昂贵渠道成本更高。

# # # 4。到达第一个值的时间（唯一的激活指标）

* *的模式:* *

用户在最初的5-10分钟内决定产品的价值。如果他们不能快速到达顿悟时刻，他们就会放弃。

**激活审计：**1. 作为新用户注册您自己的产品
2. 时间多长到第一个值
3. 数步数到aha时刻
4. 你被困在哪里了？

**如果TTFV > 10分钟，您有一个激活问题

**之前：**注册→确认电子邮件→填写个人资料→配置设置→阅读文档→第一个动作

**后：**注册→预加载样本数据→第一次动作（即刻aha时刻）

* *具体修复:* *

1. **预加载样本数据。**用户希望看到价值，而不是设置。立即给他们一个实际的例子。
2. **跳过不必要的设置。**电子邮件确认，个人资料，设置-所有可以等到之后的aha时刻。
3. * *进步的披露。**不要提前展示所有功能。从一个核心工作流开始。逐步揭示复杂性。
4. 展示，而不是讲述。**互动教程>视频>文本文档。让他们点击完成工作流程。

* *常见的错误:* *假设用户会阅读文档。他们不会。他们会点击5分钟，如果没有效果，他们就会离开。

# # # 5。$5K→$50K的变化（当PLG破裂时）

* *的模式:* *

PLG的工作为1000 - 10000美元的ARR。在2万至5万美元之间，由于组织摩擦的出现，采购、法律、安全、多方利益相关者的参与，动议被打破。

**混合方法：**

**PLG ($0-$10K):**自助注册→免费层→付费层→信用卡结帐→自动入职

**销售辅助（$1 -$5万）：**自助发现→销售参与使用信号→人工协商合同→专门的入职

**企业（5万美元以上）：**对外或对内领导→演示→POC→提案→legal/security审查→执行发起人

**PQL信号（何时触发销售）：**- **使用深度：**每日活跃，使用的核心功能，接近极限
- **扩展信号：**来自同一公司的多个用户，团队功能，集成
- **购买信号：**请求SSO/compliance/SLAs，询问团队定价

* *切换:* *

坏：“嘿，我看到你报名了。”（冷漠、普通、破坏信任）
好：“你的团队正在跨12个repos使用[特定功能]。我们可以帮你[具体值]。想要15分钟吗？”（热情、具体、有价值）

* *常见的错误:* *

销售人员过早参与低于5000美元的交易。杀死PLG运动，吓到用户。让他们自我服务，直到他们需要帮助。

# # # 6。增长预测（不确定性计划）

* *的模式:* *

预测总是错的。计划仍然是有价值的，因为他们强迫思考和创造责任。

模型三场景：****基线（当前轨迹继续）：**
-自然搜索：35%增长→4万新用户
-付费：平→2K新用户
-社区：增长10%→新增400名用户
-总数：42.4万

**优势（如果所有增长计划都得到执行）：**
-有机：50%生长（3倍含量）→48K
-付费：2倍花费，相同效率→4K
-新倡议（伙伴关系）：斜坡→3K
-总共：55K

**缺点（如果关键通道失败）：**
-有机：0%增长→26K
-付费：CPA加倍→1K
-总共：27K

**将此用于：**
-设定基准目标（基准方案）
-弹性目标（上行场景）
-升级触发器（如果你遇到了下行，有些东西需要改变）
-资源分配（什么投入改变了？）

**每月更新：**比较预测和实际。调整模型。不要forecast-and-forget。

* *常见的错误:* *过于乐观的预测，假设一切都行得通。没有每月更新。将预测作为目标（它是一个范围，而不是一个数字）。

# # # 7。编写剧本的习惯

* *的模式:* *

知识随人而逝。目标不是一次性的胜利，而是系统化的成功。

**在每一次成功的活动或实验之后，写一个1页的剧本：**```
PLAYBOOK: [Channel/Tactic Name]

Goal: [What outcome]
Steps: [Numbered, specific enough for someone unfamiliar]
Expected Output: [Specific metrics]
Metrics to Track: [How to measure]
Risks & Mitigations: [What could go wrong]
Owner: [Name]
Last Updated: [Date]
```
测试：**能不能让一个没有参与的人来执行这个剧本？如果没有，那就太模糊了。

* *季度审查。**删除不再有效的剧本。更新那些已经进化的。这将成为你的成长操作系统。

* *常见的错误:* *

在没有记录学习成果的情况下进行实验。在理解机制之前进行缩放。把成长知识困在一个人的脑袋里。

决策树

我们应该建立PLG还是销售主导？```
Can users get value in <10 min without docs?
├─ No → Sales-led required
└─ Yes → Can they self-serve implementation?
    ├─ No → Sales-led required
    └─ Yes → Is buyer = user?
        ├─ No → Hybrid (PLG + sales-assist)
        └─ Yes → Pure PLG viable
```
保持，扩大，还是关闭这个频道？```
CAC < (LTV × margin)?
├─ No → Kill within 4 weeks
└─ Yes → 90-day retention > 60%?
    ├─ No → Optimize (improve activation/onboarding)
    └─ Yes → Scale aggressively (3x budget)
```
---

常见错误

* * 1。假设PLG总是有效**
产品复杂性+买家资历=以销售为主导的胜利。提交前测试。

* * 2。无渠道经济**
每个渠道都有CAC、留存率和LTV。跟踪他们，不然你就瞎了。

* * 3。免费层太慷慨或太有限**
太慷慨：没有转换。太有限：没有激活。允许10-20个aha时刻。

* * 4。没有生长方程**
“做更多的市场营销”并不是一种策略。映射输入→输出→每个通道的转换。

* * 5。在验证**之前进行缩放
在扩展任何渠道之前，需要4周的数据。如果经济不起作用，果断杀人。

* * 6。在一个人的头脑中成长知识**
把每一个成功的实验记录下来。

##快速参考

**PLG准备就绪：**值<10分钟+自助实现+买方=用户

**增长方程式：**活动（投入）→流量（输出）→转化率，每个渠道**渠道经济：** CAC，转化率，30/90-day留存率，LTV，每个渠道的回报，每月回顾

**杀灭标准：** CAC > （LTV × margin）→4周改善后杀灭

**PQL信号：**使用深度+扩展（多用户）+购买（SSO/compliance请求）

**销售交接：** <$10K: PLG→$10K-$50K：销售协助→>$50K：全部销售

**预测：**基线+上行+下行，每月更新
