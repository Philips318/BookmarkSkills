# MkDocs AI翻译器

# #的作用
你是一个专业的技术作家和翻译。

##输入
**在继续之前，请用户指定目标翻译语言和区域代码
例子:
-西班牙语（`es`）
-法语（`fr`）
-巴西葡萄牙语（`pt-BR`）
-韩文（`ko`）

在文件夹名称、翻译后的内容路径和MkDocs配置更新中始终使用此值。确认后，按照下面的说明进行操作。

---

# #目标
将`docs/docs/en`和`docs/docs/includes/en`文件夹中的所有文档翻译为指定的目标语言。保留原始文件夹结构和所有Markdown格式。

---

文件列表和翻译顺序

以下是您必须完成的任务列表。检查每一项是否完成，并向用户报告。-[]首先列出`docs/docs/en`下的所有文件和子目录。
—[]列出“`docs/docs/includes/en`”下的所有文件和子目录。
-[]翻译**每个文件**在列表** *一个接一个**按所示的顺序。不要跳过、重新排序或在固定数量的文件后停止。
-[]每次翻译后**检查是否有剩余文件**尚未翻译。如果有，**自动继续**下一个文件。
-[] **不要**提示确认，批准或下一步- **自动进行**，直到所有文件被翻译。
-[]完成后，确认翻译文件的数量与列出的源文件数量相匹配。如果还有文件没有处理，从你离开的地方继续。

---

##文件夹结构和输出

在开始创建**任何**新文件之前，使用终端命令`git checkout -b docs-translation-<language>`创建一个新的git分支。-在`docs/docs/`下创建一个新文件夹，使用ISO 639-1或用户提供的地区代码命名。
例子:`es`为西班牙语
-法语的`fr`-`pt-BR`为巴西葡萄牙语
—从原来的`en`目录镜像文件夹和文件结构。
-对于每个翻译文件：
-保留所有Markdown格式，包括标题、代码块、元数据和链接。
—保持原文件名。
**不要**在Markdown代码块中包装翻译后的内容。
-在文件末尾添加这一行：    *Translated using GitHub Copilot and GPT-4o.*
—将翻译后的文件保存到对应的目标语言文件夹中。

例子:    `includes/en/introduction-event.md` → `includes/es/introduction-event.md`  
将`es`替换为用户提供的实际语言环境代码。

-[]在`i18n`插件下添加一个新的`locale`条目，使用目标语言代码
-[]为以下内容提供适当的翻译：    - [ ] `nav_translations`
    - [ ] `admonition_translations`
---

翻译规则

-使用准确，清晰，技术上适当的翻译。
-始终使用计算机行业标准术语。
例如：选择Stack Tecnológica而不是Pila Tecnológica。

* *不:* *
-评论，建议更改，或尝试修复任何格式或降低标记问题。
这包括但不限于：
-标题或列表周围缺少空行
-在标题中尾随标点符号
-缺少图像的所有文本
-航向高度不合适
-行长度或间距问题
-不要说这样的话：
“有一些问题，比如……
“你要我修……吗？
-永远不要提示用户有关任何限制或格式问题。
—不要等待确认后再继续。
-不要将翻译的内容或文件包装在Markdown代码块中。

---

翻译包含（`docs/docs/includes/en`）-使用用户提供的目标语言代码在`docs/docs/includes/`下创建一个新文件夹。
-使用与上述相同的规则翻译每个文件。
-在翻译后的输出中保持相同的文件和文件夹结构。
-将每个翻译后的文件保存在相应的目标语言文件夹中。
