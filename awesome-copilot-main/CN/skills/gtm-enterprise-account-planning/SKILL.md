#企业客户规划

企业交易的战略客户规划和执行。将复杂的销售周期转化为系统的胜利——或者至少在浪费几个月时间之前知道它们什么时候会消亡。

##何时使用

* *触发:* *
-“我该如何计划这次企业交易？”
-“这笔交易已经进行了3个月了，为什么还没有完成？”
-“我应该创建一个完整的帐户计划还是简化版本？”
-“我怎么知道这笔交易是否真的在进行？”
-“MEDDICC资格”
-“制定共同行动计划”

* *背景:* *
-战略性交易高于平均ACV
-涉及多个利益相关者
—销售周期超过60天
-复杂的采购流程（法律、采购、安全）
-企业或中端市场账户

核心框架

# # # 1。如果你的地图在3周内没有更新，这笔交易就失败了

**我见过的模式：**共同行动计划（MAP）是衡量交易健康状况的唯一最佳指标。不是管道阶段。不是口头承诺。而不是“他们喜欢这个产品。”

地图告诉你一切：**

* *健康交易:* *
-地图每周更新
-客户添加他们自己的行动项目
-双方按时完成任务
- MAP中出现新的利益相关者
-日期向上移动（而不是向后推）

:用* * * *死亡
- MAP上次更新是在3个多星期前
-只有你的一方有行动项目
-标记为“待处理”的客户任务数周
-没有新的利益相关者参与
-过去的所有日期

**发生原因：**

当一笔交易是真实的，客户希望它发生。它们在做功。他们涉及到利益相关者。他们正在经历他们的过程。

当一笔交易失败时，所有的工作都由你来做。他们“太忙了”。他们会“下周回复你”。经济买家正在“旅行”。

** 3周法则：**如果你的地图在3周内没有更新，这笔交易就已经结束了——只是你还不知道而已。**我从来没有见过用陈旧的MAP完成交易。11年来一次都没有

**怎么做：**

**沉默的第一周：**发送MAP更新：“这是我们完成的。你们在（特定客户行动）方面的进展如何？”

**第二周沉默：**升级到冠军：“还没有收到MAP的回复。我们的[约会]还在轨道上吗？如果优先事项发生了变化，请告诉我。”

**沉默的第三周：**排除或重置：“似乎时机不对。我们是否应该暂停并在（时间框架）内重新连接，或者有我可以帮助解决的障碍？”

* *常见的错误:* *

继续进行交易，因为“他们说他们想要”。语言兴趣≠行动。如果他们不工作，他们就不会买。

# # # 2。EB发现问题（以及为何交易在第8周夭折）

* *的模式:* *你已经谈了8周了。POC进展顺利。冠军爱你。技术验证完成。你发送提案。

然后：无线电静默。

* *发生了什么事?你从没见过经济买家。

**经济买方（EB）是指：**的人
-控制预算分配
-做出最终采购决定
-签订合同

* *: * *
-你的英雄（他们会影响，而不是决定）
-技术领导（他们验证，而不是购买）
-参加了一次演示的副总裁（他们建议，不要签字）

**为什么交易没有EB访问就会失败：**

你根据拥护者的假设构建了商业案例。但欧洲央行有不同的优先事项：
冠军关心的是：解决他们团队的痛苦
EB关心：ROI，风险缓解，战略一致性

当您通过冠军向EB发送提案时，EB看到：
-没有上下文的价格标签
-解决他们没有说清楚的问题
-他们没有评估的风险**结果：**交易停滞或死亡。

**框架：EB验证检查表**

在发送提案之前，请验证：

-[]你确定EB了吗？（姓名、头衔，由冠军确认）
-你见过EB了吗？（视频通话最少，面对面通话最理想）
[] EB同意这个问题吗？（用他们的话说，不是你的）
EB是否同意成功的衡量标准？（他们如何衡量投资回报率）
- [] EB知道价格范围吗？（讨论了大致情况，并不意外）
EB理解时间轴吗？（实施、上线、价值实现）

如果你对其中任何一个的回答都是“不”，请不要发送提案

**如何获得EB访问：**

**问问你的冠军：**
“在我们最终确定价格之前，我想和[EB名字]讨论15分钟，以确保我们在结果和时间表上保持一致。你能介绍我们认识吗？”**如果冠军阻挡：**“我可以处理，你不需要和他们说话。”
这是一个危险信号。要么是champion没有访问权限（不是真正的champion），要么是他们害怕EB会杀死交易（这意味着交易很弱）。

* *推回去:* *
“我完全理解。与此同时，我想确保[EB]在看到价格之前看到全部价值。根据我的经验，如果经济买家不尽早参与，交易就会在采购过程中被推迟。我们能打个快速对位电话吗？”

* *常见的错误:* *

把EB会议当作“很高兴有”。5万美元以下的交易都是必须的。没有EB访问=没有交易。

# # # 3。个人胜利地图（人们为自己购买）

* *的模式:* *

企业软件采购是由委员会进行的。但委员会并不买账。人们购买。* * * *人们购买是出于个人原因：
-职业发展
-在老板面前表现不错
-减少他们的工作量
-掩护他们（CYA）
-证明他们是对的
-看起来不傻

**框架：个人胜利识别**

对于每个利益相关者，映射：

* *专业赢得:* *
-如果成功了，他们会得到什么荣誉？
-对他们个人来说，什么痛苦会消失？
-这怎么能让他们好看？

专业风险:* * * *
-如果失败了怎么办？
-如果出了问题，他们的声誉成本是多少？
-谁在内部对他们持怀疑态度？

个人动机:* * * *
-他们是新角色吗？（需要速战速决）
-面临预算削减？（需要证明支出的合理性）
-要升职吗？（需要看得见的成功）
-以前被卖主烧过？(额外的风险)

例如：工程副总裁* *专业赢得:* *
-减少团队随叫随到的负担（他们会停止向她抱怨）
-更快的事件响应（在qbr中看起来不错）
-吸引更好的工程人才（现代工具）

专业风险:* * * *
团队拒绝使用新工具（她强迫他们使用）
-迁移不顺利（停机，事故）
卖主失败了（是她挑的）

个人动机:* * * *
-新入职（6个月），需要成功
在改善正常运行时间指标的压力下
-她之前选择的监控工具失败了

**这如何改变你的推销：**

* *一般的情节:* *
“我们的平台将事件响应时间缩短了40%。”**个人获胜技巧：**
“你提到随叫随到的负担正在耗尽你的团队。我们已经看到团队在第一个月减少了40%的随叫随到页面，这有助于留存率。由于您专注于电路板的正常运行时间指标，因此改进的响应时间立即显示在您的QBR仪表板上。”

* *的区别:* *

通用=商业案例
个人=职业案例

这两个问题。但个人赢得了亲密的交易。

* *常见的错误:* *

销售只针对业务问题。“这样可以省钱。这提高了效率。”这是必要的，但不是充分的。人们需要看到这对他们个人有什么好处

# # # 4。企业账户计划结构（四部分）

一个完整的帐户计划有四个相互关联的部分。一个喂养另一个。**组件1：账户汇总**
-公司基本情况（总部、规模、行业、子公司）
-技术概况（基础设施、工具、平台）
-最重要的公司计划（来自媒体、年度报告、LinkedIn）
假设：“我们能提供什么帮助？”（在参与之前写好）
- LinkedIn关键字分析（量化他们在你的领域的投资）

**组件2：组织结构图**
-映射所有相关联系人：姓名，头衔，位置，领英，电子邮件，电话，笔记
-注意事项捕获：职责范围，技术专长，个人胜利
-包括不同级别的人员：高管、主管、架构师、领导、专家
-不要只地图买家-地图影响者，用户，潜在的阻碍者**组件3：机会计划(MEDDICC)**
- **M -度量标准**：客户如何衡量成功？（经EB验证）
- **E -经济买家**：谁有预算权限？你见过他们吗？
- **D -决策标准**：他们将使用什么标准来决定？（技术、商业、政治）
**D -决策过程**：他们的购买过程是什么？（采购、法律、安全审查）
- **I -确定的疼痛**：他们明确表达了哪些具体的疼痛？（他们的话，不是你的）
- **C - Champion**：谁在账户内积极地代表你销售？
- **C -竞争对手：他们还在评估谁？竞争动态是什么？

附加：Issues/Risks表，包含缓解计划、所需帮助、责任方**组成部分4：共同行动计划(MAP)**
-联合时间表：行动，你的所有者，客户所有者，其他相关人员，截止日期
-双方必须有行动-如果只有你的团队有行动，这不是交易，这是一个演示
-轨道状态（complete/in-progress）
-使用MAP作为登记电话的运行日程
- **如果MAP在3周内没有更新，交易就失败了**

* *决策标准:* *

按潜在交易规模计算，前10-20%的账户值得投资的全账户计划。对于其余部分，使用简化版本（摘要+ MEDDICC +下一步）。

* *常见错误:* *
-在交易开始后创建账户计划（在第一次交易前创建）
-没有每周维护MAP（过期MAP =过期交易）
-填充MEDDICC假设，而不是验证的信息
-只映射明显的联系人，而不是完整的组织结构图
-不追踪每个利益相关者的个人利益

---# # # 5。LinkedIn关键字分析帐户智能

在参与战略客户之前，通过LinkedIn量化他们在你领域的投资。

**如何执行：**

1. 定义8-10个与你的领域相关的关键词（例如，类别术语，技术角色，工作流程关键词）
2. 在LinkedIn上搜索“[公司名称]+[关键字]”并记录计数
3. 地图集中：哪些位置？哪个部门?
4. 识别异常值（特定部门中关键字的高集中度标志着成熟度）

**为何有效：**

如果一家公司有50名员工，他们的个人资料中有“SRE”，那么他们在站点可靠性方面就很成熟。如果他们有两个，他们还没有准备好使用先进的可观测性工具。

这告诉你：
-是否继续追查这个账号（他们有团队吗？）
-目标是谁（集中在哪里？）
-如何个性化外展（参考他们的具体背景）

* *的例子:* *搜索“[Company] + DevOps”
- 120个结果→成熟的DevOps组织，很适合
- 5结果→早，没准备好

搜索“[公司]+ SRE”：
- 50个结果→他们关心可靠性，节距uptime/incident减少
- 0结果→不要使用SRE值道具

* *常见错误:* *
-只搜索职位名称（变化很大）而不是关键词（一致）
-不将计数与员工总数进行比较
-没有令人耳目一新的分析（招聘趋势每季度变化）

# # # 6。统一销售流程（阶段门）

企业销售遵循明确的阶段和明确的退出标准。没有达到标准就不要进入阶段。**阶段0 -管道生成：**勘探→合格权益确认
**阶段1 -发现：**Environment/pain/requirements→识别痛点，映射利益相关者
**第二阶段-演示：**产品演示，建立冠军→确定冠军
**第三阶段-验证值：**POC/trial→技术验证完成
**阶段4 -提案：**定价、条款、范围→提交提案，与EB保持一致
**阶段5 -文件流程：**法律、采购、安全→获得批准
**第六阶段-成功完成：**交易签署→客户成功移交

**退出标准事项：**

不要从第二阶段移动到第三阶段，直到你有一个冠军。
在达到POC成功标准之前，不要从阶段3移动到阶段4。
在EB批准之前不要从第4阶段移动到第5阶段。

* *常见的错误:* *根据活动而不是标准推进阶段。“我们演示过了，所以我们在第三阶段”——但如果他们没有同意POC，你就还在第二阶段。

决策树

我需要一个完整的帐户计划吗？```
Is deal size above average ACV?
├─ No → Simplified plan (summary + MEDDICC)
└─ Yes → Continue...
    │
    Sales cycle >60 days?
    ├─ Yes → Full account plan
    └─ No → Simplified plan
```
这笔交易真的在动吗？```
Is MAP being updated weekly?
├─ Yes → Healthy
└─ No → Continue...
    │
    Has it been >3 weeks since last MAP update?
    ├─ Yes → Dead deal (qualify out or reset)
    └─ No → At risk (escalate to champion)
```
我应该发送提案吗？```
Have you met the Economic Buyer?
├─ No → Don't send yet (get EB access first)
└─ Yes → Continue...
    │
    Does EB agree on problem and success metrics?
    ├─ Yes → Send proposal
    └─ No → Align with EB before sending
```

常见错误

* * 1。创建帐户计划太晚**
-在第一次接触之前建造，而不是在交易开始之后

* * 2。医学充满了假设
与客户确认每个要素，不要猜测

* * 3。陈旧的共同行动计划**
-如果MAP不是每周更新，交易就会停滞。3周以上=死亡。

* * 4。只映射买家**
-需要完整的组织结构图：影响者，用户，阻碍者

* * 5。无视个人利益**
-人们购买是出于career/reputation原因，而不仅仅是商业投资回报率

* * 6。没有跟踪交易运行状况**
-Green/yellow/red指标提前发现垂死交易

* * 7。跳过冠军验证**
-没有内部冠军，你只能独自销售

##快速参考**MAP运行状况检查：**
-绿色：每周更新，双方都有动作，客户完成任务
-黄色：每两周更新一次，主要是你的行动，客户反应缓慢
-红色：过期3周以上，只有你的行动，客户没有反应→**交易失败**

* * MEDDICC验证:* *
-[]指标：符合EB的成功标准
-[]经济买家：见过，验证过problem/solution-[]决策标准：了解他们的评价标准
-[]决策过程：知道procurement/legal/security步骤
-[]识别痛点：用客户的话说，而不是你的
-[]冠军：积极的内部销售代表你
-[]竞争：了解他们正在考虑的替代方案

**个人获胜问题：**
-“对你个人来说，成功是什么样子的？”
“如果这个成功了，你的团队会怎么样？”如果没有呢？”
-“你今年的考核标准是什么？”
-“谁在内心持怀疑态度？”为什么?”**账户计划核对表：**
- [] Account summary with hypothesis
-[]组织结构图与个人胜利映射
- [] MEDDICC完全验证（非假设）
[]客户行为MAP（不只是你的）
- [] MAP每周更新频率
