#创建模式

当输入是组件源路径或用户要求从代码生成新文档时，使用此工作流。

##输入处理

-接受代表组件的单个文件或文件夹路径。
—如果输入的是一个文件夹，分析该文件夹下的相关源文件和附近的支持文件。
-如果输入是单个文件，将其视为主要组件入口点，并根据需要检查相邻文件，以了解协作者和接口。

创建特定的需求

—将新文档保存在`/docs/components/`中。
—将文件命名为`[component-name]-documentation.md`。
—“`component_path`”设置为用户提供的源路径。
—设置“`date_created`”为当前日期。
—仅当目标区域的存储库约定在创建时希望设置`last_updated`时才设置。
—只在可以可靠地推断时填充可选元数据，如`version`、`owner`和`tags`。创建特定的分析焦点

从代码结构中确定主要组件的名称和职责。
-确定初始系统上下文、范围边界、依赖关系、设计模式和协作模型。
-根据实际公共区域建立接口表和使用示例。
—创建一个美人鱼图，为第一次看到文档的读者介绍组件的结构、依赖关系和数据流。

创建特定的输出指导-使用来自`../assets/documentation-template.md`的完整section结构。
-写一个介绍，作为一个新的概述，该组件是做什么的，为什么它存在。
-更喜欢完整的部分而不是占位符；如果信息不可用，用简短的限制说明标记该部分，而不是留下模板文本。
-只有在代码或存储库历史中存在先前版本或迁移问题的证据时，才包含更改历史或迁移注释。
