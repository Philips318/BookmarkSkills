#注解概述

注释允许您向跟踪、跨度、文档和会话添加人工或自动反馈。注释对于评估、质量评估和构建训练数据集是必不可少的。

##注释类型

Phoenix支持四种类型的注释：

|类型|目标|目的|用例|| ----------------------- | -------------------------------- | ---------------------------------------- | -------------------------------- |
| **Span注释** |个别Span |具体操作反馈|“此LLM响应准确”|
| **文档注释** |在一个检索器范围内的文档|对检索到的文档相关性的反馈| “此文档没有帮助” |
| **跟踪注释** |全程跟踪|端到端交互反馈|“用户对结果满意”|
| **会话注释** |用户会话|多回合会话反馈|“Session ended successfully”|

##注释字段

每个注释都有这些字段：

必填字段

|字段|类型|描述|| --------- | ------ | ----------------------------------------------------------------------------- |
|实体ID | String |目标实体ID (span_id、trace_id、session_id或document_position) |
|`name`|字符串|注释name/label（例如，“质量”、“相关性”、“有用性”）|

结果字段（至少需要一个）

|字段|类型|描述|| ------------- | ----------------- | ----------------------------------------------------------------- |
|`label`| String（可选）|分类值（例如“good”， “bad”， “relevant”， “irrelevant”） |
|`score`|浮点数（可选）|数值（通常为0-1，但可以是任何范围）|
|`explanation`| String（可选）|注释|的自由文本解释

**必须至少提供`label`、`score`、`explanation`中的一个**。

###可选字段

|字段|类型|描述|| ---------------- | ------ | --------------------------------------------------------------------------------------- |
|`annotator_kind`| String |谁创建了这个注释：“HUMAN”， “LLM”或“CODE”（默认为“HUMAN”） |
|`identifier`| String | upsert行为的唯一标识符（更新现有的相同名称+实体+标识符）|
|`metadata`|对象|自定义元数据为键值对|

##注释器类型

|类型|描述|示例|| ------- | ------------------------------ | --------------------------------- |
|`HUMAN`|个人手动反馈|用户评分，专家标签|
|`LLM`| LLM自动反馈| GPT-4评估响应质量|
|`CODE`|代码自动反馈|基于规则的检查，启发式|

# #的例子

* *质量评估:* *

-`quality`-综合质量（标签：good/fair/poor，得分：0-1）
-`correctness`-事实准确性（标签：correct/incorrect，得分：0-1）
-用户满意度（标签：helpful/not_helpful，得分：0-1）

* * RAG-Specific: * *

-`relevance`-文档相关性查询（标签：relevant/irrelevant，评分：0-1）
-`faithfulness`-基于上下文的答案（标签：faithful/unfaithful，得分：0-1）

* *安全:* *

-`toxicity`-含有有害物质（得分：0-1）
-`pii_detected`-包含个人身份信息（标签：yes/no）
