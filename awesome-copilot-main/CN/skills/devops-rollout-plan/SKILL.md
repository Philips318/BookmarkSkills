# DevOps Rollout计划生成器

您的目标是为基础设施或应用程序更改创建一个全面的、生产就绪的部署计划。

##输入要求

在制定计划之前收集以下细节：

###更改描述
什么在改变（基础设施、应用程序、配置）
-版本或状态转换（from/to）
-问题解决或新增功能

环境细节
-目标环境（开发、暂存、生产等）
-基础设施类型（Kubernetes, vm，无服务器，容器）
—受影响的服务和依赖项
—当前容量和规模

约束和需求
-可接受停机时间
-更改窗口限制
-审批要求
-法规或遵从性考虑

风险评估
-爆炸半径的变化
—数据迁移或模式变更
—回滚的复杂性和安全性
-已知风险

##输出格式用这些部分生成一个结构化的推出计划：

# # # 1。执行概要
-什么，为什么，何时，持续时间
—风险级别和回退时间
—对系统和用户的影响
-预计停机时间

# # # 2。前提条件和审批
-所需的批准（技术主管、安全、合规、业务）
-所需资源（容量、备份、监控、回滚自动化）
-部署前备份

# # # 3。起飞前的检查
-基础设施运行状况验证
-应用程序运行状况基线
-依赖性可用性
-监控基线指标
-Go/no-go决策清单

# # # 4。逐步推出流程
阶段：预部署、部署、逐步验证
—每个步骤的具体命令
—每个步骤后的验证
-工期估计# # # 5。验证信号
**立即**（0-2分钟）：部署成功，pods/containers启动，健康检查通过
**短期**（2-5分钟）：应用程序响应，错误率可接受，延迟正常
**中期（5-15分钟）：持续的指标，稳定的连接，整合工作
**长期**（15分钟以上）：无退化，容量健康，业务指标正常

# # # 6。回滚过程
**决策标准**：何时启动回滚
**回滚步骤**：自动、基础架构恢复或完全恢复
**回滚后验证**：确认系统健康恢复
**沟通**：通知利益相关者

# # # 7。沟通计划
-部署前（t -24小时）：时间表和影响通知
—部署开始：启动通知
—进度更新：每隔X分钟更新一次状态
—Completion：成功确认
—回滚（如果需要）：发出通知**利益相关者矩阵**：通知谁，何时，通过什么方法，用什么内容

# # # 8。部署后的任务
—即时（1h）：验证是否满足标准，查看日志
-短期（24小时）：监控指标，检查错误
-中期（1周）：部署后回顾，总结经验教训

# # # 9。应急计划
场景：部分故障、性能下降、数据不一致、依赖失败
症状，反应，时间线

# # # 10。联系信息
-主次随叫随到
-升级路径
-紧急联系人（基础设施、安全、数据库、网络）

##计划定制根据：
—**基础设施类型**:Kubernetes、vm、serverless、数据库
- **风险等级**：低（简化）、中（标准）、高（附加门）
- **变更类型**：代码部署、基础架构、配置、数据迁移
- **环境**：生产（完整计划），阶段（简化），开发（最小）

# #还记得

—始终有一个经过测试的回滚计划
-尽早和经常沟通
-监控指标，而不仅仅是日志
-记录一切
—从每次部署中学习
永远不要在周五下午部署（除非非常重要）
—不要跳过验证步骤
-永远不要假设“它应该工作”
