#技术产品定价


##初步评估

在建议定价之前，请了解：

1. **产品类型**:API/platform、开发工具、SaaS应用、基础设施？
2. **当前定价**：你们现在的定价是多少？这样有多久了？
3. **GTM运动**：自助式、销售辅助式、企业式还是混合式？
4. 成本结构：每customer/user/unit的边际成本是多少？
5. **竞争格局**：替代方案的成本是多少？（包括“什么都不做”）

---

核心框架

# # # 1。没人注意到价格上涨（你可能被低估了）

* *的模式:* *

平台公司，成长阶段。自发布以来，定价一直没有改变。企业客户为一个产品支付15K/year美元，为他们节省了20万美元以上的工程时间。

领导辩论：“如果我们提高价格，我们就会失去客户。”

**实际情况：**将企业级从$15K提高到$45K/year.添加了专门的支持，SSO，审计日志来证明跳跃的合理性。

丢失：0个企业客户。零。

获得：每个企业账户3倍的收入。另外，留下来的客户开始更认真地对待产品——更高的采用率，更多的内部冠军，更多的扩张。

**发生原因：**

技术创始人将定价与成本挂钩（“我们为他们提供服务需要花费X美元，所以我们收取2X美元”）。企业买家将定价与价值挂钩（“这为我们节省了20万美元，所以4.5万美元很便宜”）。

**定价合理性检查：**

对于每个客户细分，计算：```
Value Ratio = Customer's alternative cost / Your price

If Value Ratio > 10x → You're massively underpriced
If Value Ratio > 5x  → You're underpriced (most startups are here)
If Value Ratio 3-5x  → Healthy pricing
If Value Ratio < 3x  → Approaching ceiling
If Value Ratio < 2x  → You're expensive (need strong differentiation)
```
**如何计算替代成本：**

-人工流程小时数×小时率×频率
-内部建造成本（工程师×月×负载成本）
-现有工具成本+转换成本+转换期间的生产力损失
-未解决问题的成本（事故、停机时间、客户流失）

* *常见的错误:* *

将你的价格与竞争对手进行比较，而不是与客户的替代成本进行比较。竞争对手让你陷入一场逐底竞赛。价值将你锚定在客户实际节省的东西上。

# # # 2。三种定价模式（以及每种模式何时失效）

**模型1：基于座位的($X/user/month)**

* *工作时间:* *
-价值随用户数量而变化（协作工具、通信）
—不同用户的使用情况比较统一
-你想要可预测的收入* *休息时间:* *
-高级用户和休闲用户获得相同的价格（休闲用户流失）
-产品价值不随席位的变化而变化（一个管理员配置1000个用户）
-客户合并座位以降低成本（使用率上升，收入不变）

**模型2：基于使用($X/unit)**

* *工作时间:* *
-使用情况因客户而异（API调用、计算、存储）
边际成本是有意义的（你需要使用收益来跟踪）
—价值与使用直接相关

* *休息时间:* *
客户无法预测账单（月底的标签冲击）
-低使用率客户不值得支持
-高使用率的客户协商批量折扣，压缩利润

**模型3：基于结果($X/result)*** *工作时间:* *
-你可以可靠地衡量结果（产生的线索，解决的问题，部署的代码）
-成果直接为客户创造价值
-你们对产品的有效性有信心

* *休息时间:* *
结果取决于你无法控制的因素
-测量有争议（“铅不是来自你的工具”）
-客户对指标进行博弈

**通常获胜的混合：**

平台费用（包括您的固定成本）+usage/outcome变量（随值缩放）。

例如：$500/month基数+每个事务$0.05（或API调用、完成的任务、处理的记录——无论您的价值单位是什么）。

为什么这样做：
-基本收费确保每位客户都能支付服务成本
-可变费用使价格与价值保持一致
-客户可以在自然扩展时预测最低支出（基础）
-当客户增长时，你抓住了优势

# # # 3。免费模式的门槛设计（从免费到付费）* *的模式:* *

开发者工具最困难的定价决策是：免费和付费的界限在哪里？

**框架：找到生产边界**

从不付费的免费用户很好——他们创造了知名度、社区和内容。问题在于“生产用户”从不付费。

**如何找到边界：**

绘制您的使用分布：```
Usage Level          |  User Type        |  Willingness to Pay
─────────────────────────────────────────────────────────────
<100 units/mo        |  Hobbyist/learner |  $0 (never paying)
100-1K units/mo      |  Side project     |  $0-20/mo (maybe)
1K-10K units/mo      |  Production use   |  $50-200/mo (will pay)
>10K units/mo        |  Business-critical|  $200-2K/mo (must pay)
```
**设置你的免费层限制刚好低于生产使用开始。**在本例中：1000units/monthfree。

原因：业余爱好者和学习者保持免费（他们是你的营销引擎）。生产用户自然会达到极限并转换（他们有预算）。

**三种类型的免费付费触发器：**

* * 1。使用限制**（最常见的平台）
-免费：1,000units/month（API调用，任务，记录，无论你的价值单位是什么）
—当：生产使用超出限制时触发
-转换信号：用户正在构建一些真实的东西

* * 2。Team/collaboration闸门**（最适合工具）
-免费：个人使用
-触发时：用户邀请第二个人
—转换信号：工具有足够的价值，可以共享

* * 3。企业功能门**（最适合平台）
-免费：核心功能
—触发时间：需要单点登录、RBAC、审计日志、sla
-转换信号：IT/securityinvolved（实际部署）

* *常见的错误:* *免费层设置过高（“我们希望开发者喜欢我们”）。如果生产用户没有达到限制，他们永远不会转换。免费层的慷慨应该针对“学习者”，而不是“生产用户”。

# # # 4。企业定价（对话，而不是数字）

* *的模式:* *

企业定价不是你网站上的一个页面。这是一次谈话。“联系销售”按钮之所以存在，是因为企业交易有独特的需求——也因为你应该基于价值而不是菜单来定价。

**企业定价变量：**

* * 1。部署模式**（自助云、专用云、本地部署、混合）
-每个服务有不同的成本→不同的价格下限
-本地命令比云高2-5倍（支持复杂性）* * 2。使用规模**（座位数、API量、数据量）
-批量折扣不应低于服务成本+ 40%的利润率
-折扣价，不是折扣价

* * 3。支持级别**（社区、标准、高级、专用）
-高级支持：1.5-2倍的基本价格
-专用CSM: 2-3倍基本价格
-24/7支持SLA：基础价格的3-5倍

* * 4。合规性要求** （SOC 2、HIPAA、FedRAMP、数据驻留）
-每次合规都会增加实际成本（审计、基础设施、流程）
-相应的价格：每个合规标准的1.5-2x基数

**企业定价对话：**

当客户问“要花多少钱？”：

1. 不要用数字回答。**用问题回答：“这取决于你的部署和规模需求。告诉我你需要什么。”2. **映射其需求：**
-多少users/seats/units？
-云还是内部部署？
-合规需求？
-支持期望？
-集成需求？

3. **在呈现价格之前锚定价值：**
-“根据你的描述，你目前在这个问题上花费了X。我们的解决方案通常可以将这一比例降低Y%。”
-然后将价格作为储蓄的一部分。

4. **呈现3个选项：**
-好：满足最低要求
-更好：满足要求+拥有很好（锚定在这里）
一切，包括他们没有要求的东西
-大多数买家选择更好的。这是你的真实价格。

* *常见的错误:* *

在您的网站上发布企业定价。一旦你公布了一个数字，那就是上限——谈判只会从那里开始。将企业定价作为一种对话。

# # # 5。定价作为定位信号

* *的模式:* *你的价格告诉买家你要卖给谁。这既是一个定位决策，也是一个收益决策。

* *价格信号:* *

**$0（开源/免费层）：**
- Signal：我们是为那些想要在购买前试用的开发者准备的
-吸引：个人贡献者，实验者
-风险：被认为“不适合企业”

* * $20-100/month: * *
-信号：我们是为团队和小企业
-吸引：自助买家，创业公司
-风险：企业不会把你当回事（太便宜了）

* * 500 - 2,000/month: * *
-信号：我们是为生产工作负载
-吸引：有实际预算的成长型公司
-风险：初创公司定价过高（可能需要免费层）

* * 5000 - 50美元,000/year: * *
-信号：我们为企业服务
-吸引：中端市场和企业
-风险：需要销售团队（这个价格不能自助服务）* * $ 100 k + /年:* *
-信号：我们是关键任务基础设施
-吸引：大型企业
-风险：销售周期长，支持期望高

**定位测试：**

如果你的定价是$50/month，但你想要的是企业客户，那么你的价格会削弱你的定位。企业买家将低价格与低价值联系在一起。你可能需要*提高*价格来吸引你想要的顾客。

* *常见的错误:* *

为你现有的客户而不是你想要的客户定价。如果您的路线图是企业级的，那么价格就是企业级的——即使这意味着今天会失去一些中小企业客户。

# # # 6。何时以及如何提高价格

* *时间的信号:* *

-大多数客户的价值比为bbb50倍
胜率在40%以上（你不会因为价格而输）
-在过去6个月内没有客户对价格提出异议
-客户扩张速度快于预期
-竞争对手提高了价格，但没有失去市场份额**如何在不失去客户的情况下筹集资金：**

* * 1。老客户**（12-24个月）
-仅针对新客户的新定价
-现有客户得到通知+时间表
-为客户创造紧迫感（“价格正在上涨”）

* * 2。增加价值来证明增长的合理性
-新层有新功能，价格更高
-移动当前层的特性到更高的层
-这是重新定位，而不仅仅是价格上涨

* * 3。合同中的年增长条款**
-在企业合同中包含5-10%的年度扶梯
-使价格上涨正常化
-防止“我们4年来一直支付相同的费用”的对话

* *沟通:* *

“我们正在投资（具体的改进）。为了保持这种投资水平，我们将在[日期]更新我们的定价。你目前的保险计划会被锁定在你目前的保险费率上，直到你的退休日期。”永远不要因为涨价而道歉。将其描述为对他们喜爱的产品的投资。

决策树

哪种定价模式？```
Does usage vary >5x between customers?
├─ Yes → Usage-based (or hybrid with usage component)
└─ No → Continue...
    │
    Does value scale with team size?
    ├─ Yes → Seat-based
    └─ No → Continue...
        │
        Can you measure customer outcomes reliably?
        ├─ Yes → Outcome-based (or hybrid)
        └─ No → Platform fee + feature-based tiers
```
我们应该提高价格吗？```
Is value ratio > 5x for most customers?
├─ Yes → Raise prices
└─ No → Continue...
    │
    Are win rates > 40%?
    ├─ Yes → Price isn't the problem, but consider raising
    └─ No → Continue...
        │
        Are you losing deals specifically on price?
        ├─ Yes → Don't raise. Improve value or segment better.
        └─ No → Something else is wrong (product, positioning, sales)
```
