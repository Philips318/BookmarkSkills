#评估者：概述

何时以及如何构建自动评估器。

##决策框架```
Should I Build an Evaluator?
        │
        ▼
Can I fix it with a prompt change?
    YES → Fix the prompt first
    NO  → Is this a recurring issue?
          YES → Build evaluator
          NO  → Add to watchlist
```
**不要过早地自动化。**许多问题是简单的提示修复。

评估者要求

1. **明确的标准** -具体，而不是“它好吗？”
2. **标记测试集** - 100+人类标签的例子
3. **测量精度** -部署前了解TPR/TNR评估器生命周期

1. **发现** -错误分析揭示模式
2. **设计-定义标准和测试用例
3. **实现** -构建代码或LLM评估器
4. **校准** -根据人类标签进行验证
5. **部署** -添加到experiment/CI管道
6. **监控** -跟踪准确性随着时间的推移
7. **维护** -随着产品的发展而更新

不要自动化的东西

- **罕见问题** - <5个实例？监视名单，不要建造
- **快速修复** -可通过提示更改修复？修复它
- **不断发展的标准** -首先稳定定义
