自定义模式参考

关于在存储库、组织和企业级使用正则表达式定义自定义秘密扫描模式的详细参考。

# #概述

自定义模式扩展秘密扫描，以检测默认模式未涵盖的特定于组织的秘密。它们被定义为正则表达式，可以选择性地强制执行推送保护。

模式定义

必填字段

|字段|描述||---|---|
| **模式名称** |模式|的人类可读名称
| **秘密格式** |与秘密|匹配的正则表达式

###可选字段（通过“More options”）

|字段|描述||---|---|
| ** secret** |必须出现在secret |之前的内容的正则表达式
| ** secret** |必须出现在secret |之后的内容的正则表达式
| **额外的匹配要求** |对匹配|的额外约束
| **测试字符串样例** |验证正则表达式|的示例字符串

Regex语法

自定义模式使用标准正则表达式。常见的模式:```
# API key with prefix
MYAPP_[A-Za-z0-9]{32}

# Connection string
Server=[\w.]+;Database=\w+;User Id=\w+;Password=[^;]+

# Internal token format
myorg-token-[a-f0-9]{64}

# JWT-like pattern
eyJ[A-Za-z0-9_-]+\.eyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+
```
在before/after字段中使用类似于GitHub Actions工作流语法的过滤器模式进行全局样式匹配。

##按范围定义模式

存储库级别

1. 存储库设置→高级安全
2. “秘密保护”下→自定义图案→**新图案**
3. 输入模式名称、正则表达式和可选字段
4. **保存并运行以进行测试
5. 评审结果（最多1,000个匹配项）
6. **满意时发布模式**
7. 可选启用推送保护

**前提条件：**存储库必须启用Secret Protection。

组织级别1. 组织设置→高级安全→全局设置
2. 在“自定义图案”下→**新图案**
3. 输入图案细节
4. **保存和试运行** -选择测试库：
—组织中的所有存储库，或者
—最多10个选定存储库
5. **满意时发布模式**
6. 可选启用推送保护

* *注:* *
—组织级自定义模式的推送保护仅适用于启用了推送保护的repos
-组织所有者和回购管理员收到警报

企业级别

1. 企业设置→策略→高级安全→安全特性
2. 在“秘密扫描自定义图案”下→**新图案**
3. 输入图案细节
4. **保存和试运行** -选择最多10个存储库
5. **满意时发布模式**
6. 可选启用推送保护* *注:* *
-只有模式创建者可以编辑或运行企业级模式
—干运行需要管理员访问所选存储库
—推送保护需要启用企业级的秘密扫描推送保护

##干运行过程

针对存储库内容干运行测试模式，而不创建警报。

1. 定义图案后，点击**保存并运行**
2. 选择目标存储库（org/enterprise级别）
3. 点击* * * *
4. 审查多达1000个样本结果
5. 识别误报
6. 编辑模式并在需要时重新运行
7. **仅在假阳性率可接受的情况下发布模式**

>预演是必要的——总是在发布前测试，以避免警报噪音。

管理发布的模式

编辑模式发布后，可以对图案进行编辑：
1. 导航到自定义模式
2. 修改正则表达式或可选字段
3. 保存并预演以验证更改
4. 发布更新后的模式

###启用推送保护

只有在模式发布后才可以启用推送保护：
1. 导航到发布的模式
2. 点击“**启用**”，开启推送保护

**注意：**启用常见模式的推送保护可能会中断贡献者的工作流程。

禁用或删除模式

—禁用：停止生成新的告警，保留已有的告警
—删除：删除该模式，并停止扫描

辅助模式生成

使用Copilot秘密扫描自动生成正则表达式：1. 导航到自定义模式创建
2. 选择“使用副驾驶生成”（如果可用）
3. 提供秘密类型的文本描述（例如，“内部API密钥以MYORG_开头，后跟40个十六进制字符”）
4. 可选地提供应该匹配的示例字符串
5. 副驾驶生成一个正则表达式模式
6. 检查并改进生成的正则表达式
7. 在发布前进行测试

模式继承

|作用域|适用于||---|---|
|存储库|该存储库只有|
|组织|组织中所有启用了秘密扫描的仓库|
|企业|所有组织之间的所有回购，启用了秘密扫描|

当启用秘密扫描时，组织和企业模式自动应用于新的存储库。

最佳实践1. **发布前总是进行演练** -检查误报
2. **启动特定的** -窄正则表达式减少误报
3. **使用before/after上下文** -增加精度没有过于复杂的正则表达式
4. **用真实的例子测试** -包括应该和不应该匹配的示例字符串
5. **文档模式** -清楚地命名模式，以便团队了解他们检测到的内容
6. **定期检查** -删除或更新不再适用的模式
7. **小心推送保护** -只启用低误报率的模式
8. **考虑副驾驶** -让AI生成初始正则表达式，然后手动优化
