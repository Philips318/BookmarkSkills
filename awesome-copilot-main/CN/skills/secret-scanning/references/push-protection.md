# Push保护参考

GitHub推送保护的详细参考-防止秘密到达存储库，绕过工作流和委托绕过配置。

推保护是如何工作的

推送保护在推送过程中扫描机密，并阻止包含检测到的机密的推送。它作为一种预防控制，不像标准的秘密扫描，在提交后检测秘密。

###什么被扫描

|表面|扫描||---|---|
|命令行推送|✅|
| GitHub UI提交|✅|
|文件上传至回购|✅|
| REST API内容创建请求|✅|

###推保护类型

**库推送保护：**
-要求启用GitHub秘密保护
-默认关闭；由repo管理员、组织所有者或安全管理器启用
—在“安全”选项卡中生成绕过警报
—可以在存储库、组织或企业级别启用

**用户推送保护：**
-默认为所有GitHub.com帐户启用
-块推送到包含支持的秘密的公共存储库
当绕过时不会产生警报（除非repo也启用了推送保护）
-通过个人账户设置进行管理

解决阻塞推送-命令行当push保护阻止push时，错误信息包括：
—检测到的秘密类型
—提交包含secret的sha
—文件路径和行号
-要绕过的URL（如果允许）

###删除最近提交的秘密```bash
# Edit the file to remove the secret
# Amend the commit
git commit --amend --all

# Push again
git push
```
从早期提交中删除Secret```bash
# 1. Review the push error for all commits containing the secret
# 2. Find the earliest commit with the secret
git log

# 3. Interactive rebase before that commit
git rebase -i <EARLIEST-COMMIT>~1

# 4. Change 'pick' to 'edit' for the offending commit(s)
# 5. Remove the secret from the file
# 6. Stage and amend
git add .
git commit --amend

# 7. Continue rebase
git rebase --continue

# 8. Push
git push
```
旁路推保护

1. 从错误消息访问URL（必须是推送的同一用户）
2. 选择一个理由：
- **在测试中使用**→创建一个关闭警报（解析为“在测试中使用”）
- **这是一个假阳性**→创建一个关闭的警报（解决为“假阳性”）
- **我以后会修复它**→创建一个开放的警报
3. 点击**允许我推送这个秘密**
4. **3小时内重新推送**（之后重复旁路过程）

>当repo启用了秘密扫描时，需要一个旁路原因。对于只有用户推送保护的公共repos（没有repo推送保护），不需要原因，也不会生成警报。

##委托旁路

委托旁路使组织可以细粒度地控制谁可以绕过推送保护。

###如何工作1. 组织owners/repo管理员创建用户、角色或团队的旁路列表
2. 旁路列表上的用户可以直接旁路推送保护（有理由）
3. 所有其他贡献者必须**提交绕过请求**以供审查
4. 旁路请求出现在安全选项卡→“推送保护旁路”页面
5. 请求在**7天后过期**如果未被审核

谁总是可以绕过（无需请求）

-机构业主
-安全经理
—teams/roles中的用户加入bypass列表
-用户自定义角色具有“审查和管理秘密扫描绕过请求”的权限

###启用委托旁路

* *库级:* *
1. 设置→高级安全→推送保护
2. 启用“限制谁可以绕过推送保护”
3. 将用户、团队或角色添加到旁路列表中* *组织层面:* *
1. 组织设置→高级安全→全局设置
2. 在安全配置中配置委托bypass

管理旁路请求

指定的评论家:
1. 导航到存储库安全选项卡→“推送保护绕过”
2. 审查挂起的请求（包括秘密、提交和贡献者的评论）
3. **Approve** -贡献者可以推送secret和任何将来提交的相同secret
4. **拒绝** -贡献者必须在推送之前删除秘密

绕过请求流（贡献者视角）

1. 推送受阻；访问错误消息中的URL
2. 添加一条评论，解释为什么这个秘密可以安全地推送
3. 单击**提交请求**
4. 等待approval/denial的邮件通知
5. 如果批准：推送提交
6. 如果拒绝：删除秘密并再次推

##推送保护模式推送保护支持秘密扫描模式的子集。并非所有检测到的秘密类型都会触发推送保护块。

主要注意事项:
-推送保护可能不支持Older/legacy令牌格式
-一些模式有较高的假阳性率，被排除在推送保护之外
自定义模式可以在发布后启用推送保护

有关推送保护支持的模式的完整列表，请参阅[支持的秘密扫描模式]（https://docs.github.com/en/code-security/secret-scanning/introduction/supported-secret-scanning-patterns）。

为自定义模式配置推送保护

发布自定义模式后：
1. 在“设置→高级安全”中导航到自定义模式
2. 点击“**启用**”，开启推送保护
3. 该模式现在将阻止包含匹配秘密的推送>自定义模式的推送保护只适用于启用了推送保护的repos。为常见模式启用推送保护可能会对贡献者造成干扰。
