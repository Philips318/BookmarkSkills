#运行节奏

30人的会议结构在100人时就会崩溃。在100次崩溃时，300次崩溃时有效。失败的模式总是一样的：太多的人在太多的会议上做出太少的决定。

##何时使用

* *触发:* *
-“我们的会议不会做出决定”
“我们在成长，但联盟越来越差”
-“我们多久见一次面？”
“没人知道功能之间发生了什么”
-“永远做决定”
-“领导整天都在开会”

* *背景:* *
-公司规模从20人扩大到300人以上
-后pmf通过生长阶段
-分布式/远程团队
-任何“我们需要讨论这个”的阶段都已成为默认

核心框架

# # # 1。五级会议架构

* *的模式:* *不同的会议有不同的目的。将两者混为一谈会导致效率低下（时间过多）或混乱（决策不明确）。按功能、频率和决策权分开会议。

**第一级：每日站立（15分钟，仅限团队）**

-我们昨天完成的，今天要开始的，阻碍我们的
-最多5-10人。全公司的单口相声就是戏剧
-反模式：状态报告（使用Slack，而不是会议）
-反模式：战略讨论（错误的时间，错误的地点）
-成功标准：15分钟内完成，表面1-2个阻滞剂

**第二级：每周职能回顾（60分钟，职能领导）**

每个函数每周都有自己的节奏：
-产品团队周五下午4点：指标、用户反馈、路线图障碍
- GTM团队周二下午4点：管道，客户更新，交易健康
-工程周三下午4点：速度，bug积压，部署格式：指标回顾（10分钟）→Wins/blockers（15分钟）→一次深度分析（30分钟）→下周重点（5分钟）

反模式：试图解决会议中的每一个问题。选择1-2个，剩下的交给后续跟进。

**第三级：每周全体员工（60分钟，全公司）**

这是规模公司最重要的调整机制。

- CEO更新（15分钟）：北极星进展，本周焦点，有什么变化
-计量仪表板（10分钟）：每周相同的格式（一致性使模式识别）
-深入探讨（20分钟）：一个需要团队投入的战略主题-不是演示，而是讨论
-问答（15分钟）：真正的问题，真正的答案

反模式：防御语气。全员应该直截了当，而不是旋转。
反模式：不一致的指标。如果您更改了仪表板，团队就无法跟踪进度。

**第四级：每两周进行一次领导力培训（90分钟）**-北极星进程（5分钟）
-功能更新（30分钟，每次5-7分钟）
-需要解决的重大决策（30-40分钟）：资源冲突，战略支点，customer/product决策
-未来两周计划（15分钟）

这就是解决跨功能障碍的地方。如果职能独立运作，这次会议就行不通了。

**第5级：季度战略规划（半天至全天）**

-上一季度回顾（90分钟）：哪些是有效的，哪些是无效的，哪些是我们需要改进的
-下一季度计划（120分钟）：我们在优化什么？路线图是什么？
-功能分组（90分钟）：每个功能规划自己的季度
-综合（60分钟）：职能部门分享承诺，解决冲突

反模式：太多“有趣的活动”，而没有足够的实质内容。
反模式：没有明确的决定。

* *缩放调整:* ***<30人**：仅限2-3级。跳过每天的单口相声（你看到了一切）。跳过两周一次的领导（你就是领导）。
- **30-100人**：添加所有5个关卡。每月回顾能捕捉到你不再每天都能看到的东西。
- **100-300人**：添加跳过级别的审查。你离执行还有两层以上。
- **300+人**：添加特定功能的子节奏。CEO参加会议的次数应该少于50次，而不是更多。

**成功的法则：**

每次会议都必须作出决定，否则就取消。状态更新是异步的。如果你正在开会，没有人做决定，那就离开。

# # # 2。每周指标报告（早期发现问题的仪表板）

* *的模式:* *

每月报告延迟30天发现问题。到那时，糟糕的一个月已经过去了。每周报告在第2周捕获问题，此时您仍然可以节省一个月的时间。

**格式（每周结构相同）：**```
WEEK OF [DATE]

North Star: [Metric]
This Week: [Value] | Last Week: [Value] | Change: [+/-] [↑↓]
Context: [One sentence — why this trend matters]

Functional Metrics:
  Product:  7-Day Retention: 34% | Last: 33% | +1% ↑
            Feature Adoption: 18% | Last: 16% | +2% ↑
            Context: Onboarding improvements showing impact

  GTM:      Pipeline: $8.2M | Last: $7.8M | +$400K ↑
            New POCs: 3 | Last: 2
            Context: Partner pipeline adding deals

  Health:   Team Morale: 7.2/10 (down from 7.5)
            Context: Org restructure causing uncertainty
```
**纪律规则：**

1. **每周相同的参数。**一致性支持模式识别。可以添加参数，但不要删除它们。
2. **每个度量标准一个上下文句子。不仅仅是数字——为什么这很重要？和计划吗?还是上节课？
3. **每个指标的趋势方向。**Up/down/flat箭头。如果它大幅变动：是暂时的还是结构性的？
4. **交通灯颜色。**绿色（在赛道上），黄色（观察），红色（需要行动）。每个RED项目必须有：所有者，具体行动，截止日期。

**升级规则：**

如果同一行动计划的指标连续两周都是RED，那就升级——行动计划不起作用。

**多少参数：**

总共挑8-12个。如果一个指标在移动时不能改变你的行为，那就删除它。带有40个参数的仪表板只是装饰，而不是决策工具。

* *常见的错误:* *虚荣心指标看起来不错，但不能预测业务结果。不考虑采用情况的总下载量。首席执行官标题没有支持指标。

# # # 3。季度计划（防止战略漂移的过程）

* *的模式:* *

没有季度规划，公司就会随波逐流。每个函数都在局部进行优化。Sales追求ICP之外的交易。产品为一个客户构建功能。市场营销运行的活动没有连接到管道。

**三周计划周期：**

**第一周：回顾+数据收集**
-上一季度业绩与计划（领导准备）
-每个功能都写一页回顾：什么有效，什么无效，我们会做什么不同
财务准备：收入，支出，预测
-市场数据：竞争动向，客户反馈主题，详细分析**第二周：优先级设定（领导半天）**
-回顾（30分钟-预读，不做陈述）
-同意3-5个公司层面的优先事项
-每个：所有者，成功指标，资源需求
确定你“没有”在做什么（和你在做什么一样重要）
-解决跨职能依赖关系
-用北极星作为决胜局：“这能帮助我们达到目标吗？”优先考虑。可有可无吗?推迟。”

**第三周：OKR级联+资源分配**
-每个职能部门将公司优先事项转化为团队okr
-领导评审以保持一致性
-完成资源分配（人数、预算、工具）
-最终计划在全公司范围内共享

**季度承诺格式：**```
Q2 2026 Roadmap
North Star: [What we're optimizing for]

Pillar 1: Product (25% team effort)
  Initiative: [Name]
    Problem: [What we're solving]
    Success: [Specific metric]
    Owner: [Name]
    Timeline: [When]

Pillar 2: GTM (50% team effort)
  Initiative: [Name]
    ...

Pillar 3: People (10% effort)
  Initiative: [Name]
    ...

Pillar 4: Tech Debt (15% effort)
  Initiative: [Name]
    ...
```
**“不做”清单：**

每增加一个优先级，找出一件你要停止的事情。如果你说不出你“没有”做的事情，那么你有太多的优先事项。

* *常见的错误:* *

每季度的计划会产生一份30页没人看的文件。输出应该是：在一页上有3-5个优先级，每个都有所有者和指标。就是这样。

# # # 4。决策速度和权限

* *的模式:* *

在20人的团队中，CEO实时做出每一个决定。快。在100人的团队中，决策需要协调一致。缓慢。在300公司，决策需要协调、批准和记录。冰川。

解决办法不是开更多的会。这是明确的决策权

**决策权限矩阵：**

|决定|谁决定|时间线|升级||----------|------------|----------|------------|
公司战略CEO 1周董事会战略
|功能优先级|产品领先| 1周| CEO如果>3周|
|客户支持问题| CSM |立即|如果升级|
营销活动营销领导2周营销总监1万美元预算5
|招聘|职能领导| 2周|如果职位未获批准|
b|新的合作伙伴关系b|首席执行官b|周b|董事会战略b|
|供应商选择|功能领导者| 1周| CEO如果>$50K/year|

* *问题:* *

规模化公司开始把可逆的、低风险的决策当作不可逆转的、高风险的决策来对待。一切都需要批准。所有事情都需要开会。一切都需要共识。

* *解决办法:* *

**类型1（不可逆、高风险）：**定价模式、市场进入、主要合作伙伴→CEO/leadership一次会议辩论决定。时间：最多1-2周。类型2（可逆，低风险）：**活动创意，功能优先级，单一招聘→功能所有者决定，通知，迭代。时间：当天或次日。

**根据70%的信息做出决定，而不是100%。速度是每个阶段的竞争优势。

* *常见的错误:* *

共识文化伪装成合作。“让我们让每个人都团结起来”通常意味着“没人想做决定”。说出决定者的名字。让他们决定吧。继续前进。

# # # 5。Async-First沟通

* *的模式:* *

同步会议无法扩展。默认为async，升级为sync。

**异步优先（不需要会议）：**
-决策文件（包括重大决策文件）-撰写提案，征求意见，48-72小时反馈，决定是否达成共识或无重大异议
-进度更新（使用每周报告，而不是会议）
-工艺变更和sop
-已经做出的决定（告知，不要讨论）* *同步时间:* *
-需要实时头脑风暴
-需要解决的重大分歧
-复杂的主题需要白板
-团队建设/关系

* *文档纪律:* *

每个决定都被记录下来：决定了什么？为什么?谁决定?什么时候生效？谁需要知道？

存储在可搜索的格式（wiki，共享驱动器）。新员工入职更快。过去的决定不会被重新提起诉讼。

* *常见的错误:* *

“快速同步”会议每周会占用10个小时。在Slack上过度沟通（短暂的、嘈杂的），而在持久的格式（文档、电子邮件）上沟通不足。重要的内容应该在6个月后才能被搜索到。

# # # 6。CEO每周更新

* *的模式:* *在一家规模庞大的公司里，这是唯一一个杠杆最高的沟通工具。写5-10分钟。每个人都读它。它设定背景，庆祝胜利，确定优先事项，并创造共同的理解。

**格式（周日晚上或周一早上发送）：**

* * 1。周焦点（1段）：**
这周的首要任务是什么？团队应该关注什么？

* * 2。北极星进度（1-2发子弹）：**
我们在关键指标上进展如何？趋势up/down/flat吗?为什么这很重要？

* * 3。本周胜利（3-5个子弹）：**
运什么?Customer/partner赢了?这意味着什么？

* * 4。解决障碍（1-2子弹）：**
这周我们要解除哪些封锁？谁需要知道？

* * 5。问（1项，可选）：**
团队需要什么帮助？推荐、反馈、客户介绍？

规则:* * * *每周的同一天。一致性标志着操作纪律。如果你跳过一个星期，团队就会注意到——并开始怀疑你没有告诉他们什么。

* *常见的错误:* *

太长（团队不阅读），太详细（将其保留到职能会议上），只有好消息（团队失去信任），不一致（团队停止阅读）。

# # # 7。角色清晰度>头衔

* *的模式:* *

提高速度最有力的工具不是等级制度，而是明确的角色清晰化。当一个人确切地知道自己拥有什么，并且不能把它分派出去时，决策就会更快。

**如何执行：**

每个项目只有一个所有者（有队友支持）
-指标与该所有者绑定
成功是通过移动kpi来衡量的，而不是完成任务
-在48小时内取消没有明确所有权的计划

测试:* * * *你能说出拥有这个结果的人是谁吗？不是“团队”，而是一个人。如果你做不到，主动权就会流失。

* *常见的错误:* *

将项目分配给多人（“每个人都拥有它”=没有人拥有它）。衡量活动而不是影响。如果没有清晰的ROI跟踪，每个项目的烧钱率就会上升。

决策树

我们需要哪些级别的会议？```
Company size <30?
├─ Yes → Levels 2-3 only (weekly functional + all-hands)
└─ No → Continue...
    │
    30-100 people?
    ├─ Yes → All 5 levels
    └─ No → All 5 + skip-level reviews + function sub-cadences
```
这个会议值得保留吗？```
Does it produce decisions?
├─ No → Can it be async?
│   ├─ Yes → Make it async, cancel the meeting
│   └─ No → Redesign with decision agenda
└─ Yes → Are the right people in the room?
    ├─ No → Fix attendee list (fewer > more)
    └─ Yes → Keep it
```

常见错误

* * 1。随着你的成长增加会议
取代他们。在200人的团队中，CEO参加的会议应该少于50人。

* * 2。状态更新会议**
如果可以是电子邮件，那就应该是电子邮件。开会是为了做决定。

* * 3。每季度更改参数**
一致性使趋势识别成为可能。每次都是同一个仪表盘。

* * 4。共识文化* *
说出决定者的名字。让他们决定吧。通知其他人。

* * 5。所有信息在Slack**
短暂的，嘈杂的，无法搜索的。重要的决定是由医生做出的。

* * 6。季度计划，产生30页的文件**
在一页纸上列出3-5个优先事项。这就是输出。
