# CodeQL警报管理参考

用于理解、分类、排除和解决CodeQL生成的代码扫描警报的指南。

##警报严重性级别

###标准严重性

所有代码扫描警报都具有以下严重级别之一：

|级别|描述||---|---|
|`Error`|应该修复的高可信度、高影响的问题|
中等信心或中等影响问题|
|`Note`|低可信度或信息性发现|

安全级别

安全警报还具有从CVSS分数派生的安全严重性：

|等级| CVSS评分范围|描述||---|---|---|
|`Critical`| > 9.0 |严重漏洞，需要立即关注|
|`High`| 7.0 - 8.9 |重大漏洞优先级|
|`Medium`| 4.0 - 6.9 |正常工作流中需要解决的中等漏洞|
|`Low`| 0.1 - 3.9 |安全影响有限的小问题|

当存在安全级别时，它优先于显示和排序的标准级别。

安全级别是如何计算的

对于添加到Default或Extended套件中的每个CodeQL安全查询：
1. 所有匹配查询的CWE标签的cve都会被识别
2. 计算这些cve的CVSS分数的第75个百分位数
3. 该分数成为查询的安全严重性
4. 数值分数映射到每个CVSS定义的Critical/High/Medium/Low## Alert标签

非应用程序代码中的警报接收类别标签：

|标签|描述||---|---|
| **生成的** |构建过程|生成的代码
| **Test** |测试代码（由文件路径检测）|
| **Library** |库或第三方代码|
| **文档** |文档文件|

这些标签根据文件路径自动分配。它们不能被手动覆盖。

在拉取请求中提醒分类

PR提醒的工作原理

-警报显示为注释在**对话**选项卡和**文件更改**选项卡
- **码扫描结果**检查总结所有发现
-警报只出现在PR中，如果所有已识别的行都存在于PR diff中
-显示更改线路上的新警报；不存在预先存在的警报

PR检查失败行为

缺省情况下，如果告警级别为`error`、`critical`或`high`，则检查失败。通过存储库设置→规则→规则集→代码扫描覆盖此阈值。

###合并保护配置规则集以在以下情况下阻止PR合并：
—必需的工具查找符合严重性阈值的警报
-所需工具的分析仍在进行中
—未配置存储库所需的工具

##副驾驶自动修复GitHub CopilotAutofix自动为拉取请求中的CodeQL警报生成修复建议。

# # #的可用性
-所有公共存储库免费
-可用于私人回购与GitHub代码安全许可证
-无需订购副驾驶
-支持CodeQL查询的子集（不是全部）

###如何工作
1. 代码扫描检测PR中的警报
2. 警报信息被发送给LLM进行分析
3. 修复建议作为内联代码更改的PR注释发布
4. 开发人员审查、编辑并提交建议的修复使用自动修复建议
-点击**编辑**直接在GitHub或通过GitHub CLI应用修复
—使用“**View autofix patch**”本地应用
在提交之前总是检查和测试修复
-修复可能包括对原始PR diff中的文件的更改（例如，添加对`package.json`的依赖）

###取消自动修复
点击评论上的**驳回建议**来拒绝一条建议。

##取消警报

何时解散

在以下情况下解除警报：
-发现是假阳性（代码使用CodeQL不识别为安全的模式）
-代码仅用于测试，风险是可接受的
-修复的努力大于收益

解雇原因

选择合适的原因-它会影响查询是否继续运行：

|原因|何时使用||---|---|
| **误报** |告警错误；代码实际上是安全的
| **不会修复** |风险被接受或代码被弃用|
| **用于测试** |脆弱模式仅在测试代码|中存在

###解雇评论
-添加评论，解释解雇理由
-注释存储在audit/compliance的警报时间轴中
-可通过REST API访问`alerts/{alert_number}`→`dismissed_comment`贡献改进
对于来自不受支持的清理库的误报，请考虑向CodeQL存储库提供帮助，以提高分析的准确性。

##解决警报

修复并重新扫描
1. 修复源代码中的漏洞
2. 提交并推送更改
3. 下一次代码扫描运行将验证修复
4. 确认修复后，警报将自动关闭###删除陈旧配置
如果old/disabled配置中的警报持续存在：
1. 导航到警报的**受影响的分支**部分
2. 识别过时的配置
3. 删除过时的配置以删除过时的警报

##警报数据流

对于`path-problem`查询，警报包括数据流信息：

- **源** -不可信数据输入的地方（例如，用户输入）
- **Sink** -数据被不安全使用的地方（例如，SQL查询，HTML输出）
- **路径** -数据从源到汇的中间步骤

点击**显示路径**警报注释可视化完整的数据流。

##多配置警报当多个扫码配置分析同一文件时：
—相同查询检测到的相同问题显示为单个警报
- **受影响的分支**部分显示哪些配置发现了警报
—不同的配置可能显示不同的状态
—重新运行过期配置以同步警报状态
