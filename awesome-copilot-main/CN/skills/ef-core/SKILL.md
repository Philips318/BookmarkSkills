#实体框架核心最佳实践

你的目标是帮助我在使用实体框架核心时遵循最佳实践。

##数据上下文设计

保持DbContext类的集中和内聚
-使用构造函数注入配置选项
-覆盖OnModelCreating流畅的API配置
—使用ientitytypconfiguration分离实体配置
-考虑在控制台应用程序或测试中使用DbContextFactory模式

实体设计

-使用有意义的主键（考虑自然键和代理键）
-实现适当的关系（一对一、一对多、多对多）
-使用数据注释或流畅的API进行约束和验证
-实现适当的导航属性
-考虑为值对象使用自有实体类型

# #性能-使用AsNoTracking（）进行只读查询
-使用Skip（）和Take（）实现大型结果集的分页
-在需要时使用Include（）来加载相关实体
-考虑投影（Select），只检索必需的字段
-对频繁执行的查询使用编译查询
—合理包含相关数据，避免出现“N+1”查询问题

# #迁移

—创建小的、集中的迁移
—描述迁移的名称
—在将迁移SQL脚本应用到生产环境之前，请验证迁移SQL脚本
—考虑使用迁移包进行部署
-在适当的时候通过迁移添加数据播种

# #查询

明智地使用IQueryable，并理解查询何时执行
-首选强类型LINQ查询而不是原始SQL
-使用合适的查询操作符（Where, OrderBy, GroupBy）
—复杂操作时考虑数据库功能
-实现可重用查询的规范模式更改跟踪和保存

-使用适当的变更跟踪策略
-批量处理SaveChanges（）调用
—实现多用户场景下的并发控制
—考虑对多个操作使用事务
-使用合适的DbContext生存期（适用于web应用程序）

# #安全

—使用参数化查询避免SQL注入
—设置适当的数据访问权限
-小心原始SQL查询
—考虑对敏感信息进行数据加密
—通过迁移管理数据库用户权限

# #测试

-使用内存数据库提供程序进行单元测试
-使用SQLite为集成测试创建单独的测试上下文
-模拟纯单元测试的DbContext和DbSet
—在隔离环境中测试迁移
-考虑对模型更改进行快照测试当检查我的EF Core代码时，识别问题并根据这些最佳实践提出改进建议。
