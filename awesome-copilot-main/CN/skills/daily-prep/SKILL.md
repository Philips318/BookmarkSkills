#每日准备

为下一个工作日生成一个结构化的准备文件，包括会议细节、准备项目、关联任务和生产力建议。

##何时使用

-一天结束时：“为明天做好准备”
任何时候都可以：“为周五做准备”或者“3月25日是什么样子？”
—周规划：多天运行

# #过程

# # # 1。确定目标日期

如果用户指定了日期，则使用该日期。否则，默认为明天（当前日期+ 1天）。
如果明天是星期六，则默认为星期一。如果是星期天，则默认为星期一。
计算输出路径：`outputs/YYYY/MM/YYYY-MM-DD-prep.html`# # # 2。通过WorkIQ拉日历

使用WorkIQ MCP工具获取日历。问WorkIQ:

>“在{目标日期}我有哪些会议？”对于每次会议，包括：主题、开始时间、结束时间、组织者、所有与会者及其电子邮件地址、地点、会议是否在线以及我是否接受或拒绝。”如果回复不充分，请进行后续查询：

>“对于{目标日期}的会议，哪些会议被标记为任择会议或暂定会议？哪些是反复出现的？”

# # # 3。对每次会议进行分类

根据与会者的领域和主题应用这些标签：

|标签|标准||-------|----------|
|`[Customer · HIGH]`|来自customer/partner域的外部与会者，或主题匹配已知客户名称|
|`[Internal]`|仅限公司内部域名参与者|
论坛，社区，公会，学习会议|
|培训、工作坊、认证、学习|
|`[Optional · skip]`|暂定的、低重要性的，或者已知的可重复出现的可选选项（例如，“办公时间”、“开放问答”）|
|`[Personal]`|私人活动，非工作|

####区域标记

对于每个会议，选中组织者字段并应用这些附加标记：

|条件|标记|动作||-----------|--------|--------|
|开始≥15:30 < 16:00（任何组织者）|`⚠️ After-hours`|建议谢绝|
|开始≥16:00，**不**自组织|`⚠️ After-hours`|建议谢绝|
|开始≥16:00，自组织| _（无标志）_ | OK -您选择了|
上午9点之前|和* *不* *自组织|`⚠️ Early`学习窗口| |推荐下降——侵入
在09:00之前，自组织| _（无标志）_ | OK -您选择了|
|重叠12:00-13:00 |`🍽️ Lunch conflict`|日历笔记|

“自组织”意味着**你**是会议组织者（在WorkIQ中检查组织者字段）。

# # # 4。理想的一天安排

将此作为所有分析步骤的决策框架。每次会议都必须根据这些区域进行评估。用户应该根据自己的日常习惯调整这些时间和目标。

|区域|时间|目的|规则||------|------|---------|-------|
|早焦点| 09:00前|管理、学习、个人工作|不受他人会议干扰。标记外部事件。|
|客户区| 09:00-12:00 |客户/外部会议|最多2个客户会议。喜欢早上接外接电话。|
|午餐| 12:00-13:00 |休息|受保护。标记任何重叠。|
|深度工作| 13:00-15:30 |交付成果，专注coding/writing|尽量减少会议。将非必要的会议标记为深度工作中断。|
|受保护（严格）| 15:30-16:00 |一天结束结束|标记所有会议，无论组织者如何。|
| Protected (flex) | 16:00+ |一天结束|只标记其他人的会议。自组织好。|

**每天目标：**
-学习时间：**1.5小时**（从上午集中+休息时间开始）
-深度工作时间：**2.5h**（13:00-15:30区域）
-客户会议：**最多2次**（最好在09:00-12:00）

# # # 5。检测冲突和日适应问题比较事件时间窗口。在冲突表中标记重叠，并为每个重叠提供建议-优先考虑客户会议而不是internal/optional.还要检测这些**日适合问题**（在单独的“日适合问题”表中报告）：

|检查|条件|标志||-------|-----------|------|
| **客户超载** | |`[Customer · HIGH]`会议|标志3 +为“考虑重新安排到另一天”|
| **深度工作干扰** |非必要的会议在13:00-15:30的区域|“干扰深度工作-考虑转移到早上”|
| **不理想的位置** |在09:00-12:00之外的客户会议|“客户在首选的早晨区域之外的会议”|
| **早期入侵** | 9:00之前的其他人会议|“入侵学习窗口-建议拒绝”|
| **午餐冲突** |会议重叠12:00-13:00 |“与午休冲突”|

# # # 6。从工作区收集上下文

1. 阅读打开的任务文件，查找与明天会议的客户姓名或与会者有关的任务
2. 在工作空间文件夹中搜索与这些客户或主题相关的最新文件
3. 查看最近的会议摘要或相关准备内容的计划
4. 利用这一点，每次会议都生成可操作的准备要点# # # 7。每次会议生成准备

对于每次会议（按时间顺序），包括：
-时间，主题，组织者
-参会人员名单（名字，如果是外部公司）
- 3-5个可操作的准备要点，基于公开任务，最近总结和会议主题
—如果没有上下文，记录会议中ask/clarify的内容

# # # 8。找到学习和专注的时间

在生成每个会议的准备之后，分析当天的日程安排以找到空闲时间：

1. **早晨焦点确认** -确认早晨焦点窗口是否清晰。如果存在任何非自组织事件，则标记它。

2. **学习时段** -在上午的窗口找到≥30分钟的间隙和任何其他适合提升技能的空闲时段。目标:* *1.5h/day* *。对于每个槽：时间范围，持续时间，建议的活动。3. **深度工作块** -在13:00-15:30区域找到连续的空闲间隙来交付成果。对于每个块：时间范围、持续时间、打开任务的建议任务。

4. * *报告总数:* *
-实际学习时间vs. 1.5小时目标（例如，“1.0小时/ 1.5小时目标-短0.5小时”）
-深度工作时间为13:00-15:30（如“2.0小时/ 2.5小时”）

# # # 9。生产力的建议

分析一整天并提供：

|章节|包括什么|---------|------------------|
| **日契合度评分** |率0-100%，一天与理想日结构的契合度。标准：(1)早上焦点清晰（+20%），(2)09:00-12:00≤2次客户会议（+20%），(3)午餐12:00-13:00有保护（+15%），(4)深度工作13:00-15:30完整（+20%），(5)15:30之后没有任何内容或16:00之后只有自组织（+15%），(6)找到≥1小时的学习时段（+10%）。表现为：🟢≥80%，🟡50-79%，🔴<50%。|
| **日形** |总会议时数、可用集中时间、学习时数、深度工作时数、heavy/moderate/light评估时数|
| **谢绝候选人** |自动包含：(1)所有会议15:30-16:00，(2)其他会议≥16:00，(3)其他会议<09:00,(4)第三+客户会议，(5)深度工作区可选会议。显示“回收”栏，显示恢复的分钟数。在09:00之前或16:00之后自行组织的会议**排除**自动拒绝。|
| **冲突解决** |具体建议对于每个重叠|
| **学习槽** |技能提升缺口-从步骤8。表：窗口、持续时间、建议活动。显示总时间vs. 1.5小时目标。|
| **深度工作块** |从第8步开始，在13:00-15:30之间提供交付时间。表：窗口、持续时间、建议任务。|
| **能源管理** |如果>3小时连续的客户会议没有休息|
**最重要的3件事** * |需要完成的3件最有影响力的事情（会议+任务）|# # # 10。写文件

在`outputs/YYYY/MM/YYYY-MM-DD-prep.html`上创建输出文件，作为带有嵌入式CSS的自包含HTML文件（深色主题、颜色编码的时间线、响应式布局）。

如果该日期的文件已经存在，请先读取它并更新而不是覆盖——用户可能已经添加了手动注释。

##示例提示

——《为明天做好准备》
-“星期五长什么样？”
-“3月28日的日常准备”
-“让我为下周一做好准备——专注于客户会议”

- **WorkIQ MCP工具**必须可用于日历访问（Microsoft 365 / Outlook）
-一个带有任务文件和customer/project文件夹的工作区，用于丰富上下文
-输出是自包含的HTML -没有外部依赖
