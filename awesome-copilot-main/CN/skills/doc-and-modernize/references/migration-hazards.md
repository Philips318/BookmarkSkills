#迁移危险目录

一个通用的、与堆栈无关的、可预测的迁移危险目录
每个生态系统*，但在现代化计划的初稿中经常被遗漏。
每个阶段的计划都应该在此之前与此列表进行** **
实现**（参见现代化模式的实现前红队步骤）。

每个危险写成：**触发**（发生时）→**风险**（发生时）
→**检测探针**（一个具体的检查，你现在可以运行）→**计划行动**(什么
添加到阶段)→**示例**（每个生态系统，仅用于说明）。

>这些是*危险等级*，而不是一个堆栈的固定清单。的例子
> （Java/Spring/Mongo/Docker等）是根据实际运行图绘制的插图
>每个类到您实际迁移的任何生态系统。如果有危险
>不适用，明确地说出来，而不是默默地跳过它。

---

如何使用这个目录在实施**任何**阶段之前：

1. 看看下面的每一个危险，问问“这个阶段会触发危险吗？”
2. 对于每个触发的危险，针对真实的repo运行检测探针。
3. 将**计划行动**折叠到**之前的阶段任务和退出标准中
编写代码——在计划中发现的危险是一项任务；回顾一下
返工;被戳中是意外。
4. 记录你检查和清除的危险，而不仅仅是那些开火的危险
无声的跳跃，无异于一种思念。

根据经验（PiggyMetrics运行，0-6阶段），独立评论家抓住了一个问题
**在每个单独的阶段**阻塞计划缺口，每个缺口是一个实例
下面的类。经营这个目录*是*评论家，制度化。

## H1 -不完整的隔离/移除集**触发：**您正在删除、隔离或剪切整个依赖项
家族（一个死的框架，一个被删除的运行时API，一个EOL库集）
一些模块正在被触摸。

**风险：**你没有列出的模块仍然依赖于被删除的模块
工件，因此默认的build/test目标在切换后失败—通常在
模块计划从未提及。

**检测探针：**在**所有**清单中查找死亡的artifact/coordinate；
不仅仅是你正在编辑的那些(`pom.xml`/`build.gradle`,`package.json`，`*.csproj`、`requirements*.txt`/`pyproject.toml`、`go.mod`等)。每个命中都是一个
必须在同一阶段移动或隔离的模块。

**计划行动：**枚举死亡工件的**完整传递集**
在前面列出依赖项，并在阶段的reactor/quarantine中列出每个依赖项
的决定。显式地声明转换后的构建目标（其中包含哪些模块）；
被隔离了)。* *例子:* *
* Spring Cloud 2023移除NetflixHystrix/Turbine；`monitoring`和`turbine-stream-service`仍然拉着`netflix-hystrix-dashboard`/`netflix-turbine-stream`和破`mvn verify`即使计划只有
隔离`gateway`+`auth-service`。
*JS:*删除`request`- grep的每一个`require('request')`/ '从
“请求”，而不仅仅是你记得的一个服务。
- *Python:*删除c扩展库-检查每个`import`站点+附加项。

框架-主要的机械代码（命名空间/ API /测试引擎）

**触发：**框架、语言或平台的**重大**版本碰撞
（不是patch/minor）。主要颠簸携带*机械*破碎变化独立
按照你自己的逻辑。

**风险：**该计划将“更新版本”视为一个任务，而忽略了
整个树的机械迁移碰撞力-命名空间重命名，删除
已弃用的api，更改了testrunner/engine，更改了配置键-因此构建
甚至不能编译。**检测探头：**读取目标版本的**migration/upgrade指南**和
确定已知的突破性更改配方。为旧的命名空间/创建树
API表面的大小变化。检查是否有**生态系统codemod/recipe工具**
的存在。

**计划行动：**列举每个机械迁移作为其**自己的明确任务**；
更喜欢生态系统的自动配方工具，而不是手工编辑
可靠的。要慎重地决定是使用工具还是使用人工(小树用手可能更安全；
大树需要工具)。将测试框架迁移包含在列表中——是的
经常忘记。* *例子:* *
—*Spring Boot 2→3:*`javax.* → jakarta.*`命名空间迁移**和** JUnit 4→5
(添加`junit-vintage-engine`以保持JUnit 4测试运行，迁移`OutputCapture`风格的仅限木星的情况)。工具:* * OpenRewrite * *。
*JS:* CommonJS→ESM，或者React类→hooks。工具：** jscodesshift **、`react-codemod`。
- *Python:*`2to3`/`pyupgrade`；`async`API重命名。
- *。*`Newtonsoft`→`System.Text.Json`，`HttpClient`模式。

## H3 -运行时不与部署工件同步

**触发：**你碰撞**language/runtime主要** (JDK, Node, Python, Ruby，
Go)用于*构建*应用程序。

**风险：**构建现在为新的运行时发出构件，但是
**deployment/runtime面**仍销旧一基图像，CI流道
版本，构建包，`engines`字段，lambda运行时-所以应用程序构建绿色
然后失败*运行* （bytecode/ABI/syntax不匹配），往往只在一个smoke/e2e步骤，或在prod中静默。**检测探头：**盘点每一个地方的运行时版本是固定的：`Dockerfile`/`Containerfile`基础映像、`docker-compose*`构建上下文、CI
工作流程`setup-*`/流道图像，`.tool-versions`/`.nvmrc`/`runtime.txt``package.json`中的`engines`，无服务器运行时密钥。互相核对
新目标。

**计划行动：**添加一个显式任务来移动**每个**deployment/runtime引脚
与构建碰撞相同的阶段。永远不要让构建-运行时和运行-运行时漂移
跨越一个相边界。验证烟雾路径实际上builds/runs的新
工件（并且不构建隔离模块）。

* *例子:* *
- *JVM:*源代码构建的服务发出JDK 21字节码，但每个`Dockerfile`仍然`FROM java:8-jre`→容器无法启动；开发-撰写仍然*构建*
隔离`auth-service`。
*节点：* CI跳到22号节点，但Docker镜像仍然是`node:14-alpine`。
*Python:* venv在3.12上，但容器基础是`python:3.7`。

---## H4 -流量/路由类枚举间隙（edge & auth重写）

**触发：**重写edge/gateway，auth/identity层，或任何request-routing/security边界。

**风险：**计划锁定明显的验证快乐路径并无声地掉落
一个或多个*其他*流量类-匿名流(注册，密码重置，
公共资产、服务对服务调用、网络钩子等等
它们在交叉点断裂。

**检测探针：**枚举**边界必须服务的每个路由类**：
(1)anonymous/public,(2)终端用户认证，(3)服务对服务
（机器tokens/scopes）， (4)infra/observability（运行状况、准备情况、度量）
(5)webhooks/callbacks.对于每个配置，确认新配置具有显式的
规则。**使route-class枚举成为。类的显式工件
阶段（路由类表→新规则→作用域）。大声说出来scanners/security期望基础设施端点（例如指标刮擦）保持不变
可及。决定s2s调用的token/scope粒度（窄范围，而不是大范围）
通用“服务器”授权)。

* *例子:* *
- *BFF/OAuth2:* SCG BFF + TokenRelay覆盖登录，但错过了**匿名
注册POST +注册资产**，`/uaa/users`改为`permitAll`需要一个狭窄的`user.write`服务范围。
- *指标：*资源服务器安全必须保持`/actuator/prometheus`打开或
刮痧无声地破裂。

## H5 -有状态数据存储的主要升级被视为image/version碰撞

**触发：**碰撞**主版本**的有状态的后台服务
（数据库、缓存、代理、搜索索引）**持久化data/volumes**。**风险：**引擎专业经常无法启动先前主要的磁盘数据
没有sequential/FCV升级路径。天真的形象碰撞要么无法启动，
根据本地卷状态显示不稳定，或损坏数据。

**检测探针：**检查存储是否持久化了volumes/data目录，并读取引擎支持的升级路径(顺序专业？
feature-compatibility-version步骤?dump/restore只?)。确定
数据为production/durable或ephemeral/demo.**计划行动：**选择并记录**一个**路径：(a)sequential/FCV迁移
与步骤+回滚，或(b)一个**显式的破坏性重置**（掉落卷），
重新播种)，当数据是ephemeral/demo时——这是一个决定，而不是一个意外。
将其与回滚计划一起放入迁移安全网中。* *例子:* *
*MongoDB 3→7:*直接映像碰撞到现有的匿名`/data/db`卷
是不安全的;对于一个演示，祝福路径是`docker compose down -v`+
通过本机`initdb.d`重新播种，保留旧的`mongo:3`映像
回滚。
*Postgres major:*需要`pg_upgrade`或dump/restore，而不仅仅是一个标签的改变。

## H6 -过渡-不安全状态反复触发扫描器和检查器

**触发：**一个阶段有意引入一个临时的，故意弱
保持系统在迁移过程中可运行的状态-允许所有安全漏洞，
禁用CSRF、打开的端点、硬编码的秘密占位符、禁用
检查。

**风险：**每个代码扫描器（CodeQL, Dependabot， SAST）和每个自动化
审稿人在每次审查时都会标记它，从而产生重复的噪音和重复的诉讼。
更糟糕的是，这艘船本来只是暂时的，但却无声无息地航行着，因为
没有人跟踪它的收尾阶段。**检测探头：**对于每一个过渡性减弱，询问：哪个扫描仪将
标记这个，然后哪个阶段关闭它？弱化的范围是否“最低限度”
(例如，permit-all链仍然应该显式禁用form-login/HTTP-Basic表面正是我们想要的)？

**计划行动：**维护一个**过渡-不安全状态寄存器**：每个shim
(a)为什么需要它，(b)关闭它的阶段，(c)剩余风险，
(d)给审稿人的注释，说明它是由设计直到阶段n。每次削弱的范围
越紧越好。预先声明它会将评论混乱转化为已解决的问题，
跟踪的决定。

* *例子:* *
-阶段5允许-所有`SecurityConfig`shims标记CodeQL“CSRF禁用”打开
每一次服务，每一次评论；修复方法是显式禁用form-login/basic并注释“无国籍许可证-所有shim，在第n阶段关闭”

## H7 -堆叠pr陷阱&主干脑裂（分阶段治理）**触发：**多阶段迁移，每个阶段都依赖于前一个阶段，
branch-per-phase开发。

**风险：**如果阶段N+1从阶段N的分支（而不是主干）分支出来，并且
阶段N永远不会合并到主干，pr会相互合并到主干
静默地延迟几个阶段，后面的阶段被迫堆叠
生成必须重写“无堆叠pr”规则的确切绑定。
一个并行的失败：一个带有两个默认分支的回购（`master`+）`main`)，其中相位工作针对错误的一个。

**探测探针：**每一阶段开始前，需要验证前一阶段的PR为
**合并到主干**，新分支从主干**中删除**
来源/<trunk>. .在创建分支时，HEAD '应该为空)。确认回购
真实的主干名称，并且没有遗留的默认分支作为目标。**计划行动：**授权**在开始下一个阶段之前将每个阶段PR合并到主干
阶段* *。永远不要将相位branch/PR建立在兄弟相位分支上。如果真的
阻塞和控制堆叠是不可避免的，需要一个**调解PR**
这将使堆栈落在主干和一个明确的“剩余风险说明”上。销的
Trunk名称并标记任何遗留的默认分支“仅历史-不目标”。

* *例子:* *
- PiggyMetrics阶段3和4相互合并；`main`停留在第二阶段；`master`/`main`分裂的大脑-只有一个专门的PR #6，之后
第五阶段必须打破禁止堆叠的规则。

## H8 -动态文档漂移（拓扑变化超过文档）

**触发：**相变系统**拓扑** -module/reactor成员，
删除服务、重命名分支、更改命令、new/removed端点。**风险：**只有计划的状态标记被更新；* *executable/onboarding文档** (`.github/copilot-instructions.md`,`README`，模块列表，命令
表)变得陈旧，并开始主动误导下一个agent/human-例如a
不再与反应堆匹配的“隔离模块”列表。

**探测探针：**任何拓扑更改后，将更改对每个文档进行差分
*描述*拓扑：代理指令文件，README，架构文档module/command表，compose/service库存。

**计划行动：**将**生活计划纪律**扩展到计划文件之外；
任何改变拓扑结构的阶段都必须更新`copilot-instructions.md`README，以及同一PR中的任何module/topology列表**。将这些文档视为
这是该阶段完成定义的一部分，而不是后续工作。* *例子:* *
-在`gateway`移动后，`copilot-instructions.md`隔离文本保持失效
进入反应器和`monitoring`/`turbine`分别去除；README硬编码a`master`分支链路即干线404d后变为`main`；致动器
曝光省略了`refresh`，打破了`@RefreshScope`的工作流程。
