#本体说明

该文件定义了维护和发展上下文图所使用的动态本体的规则。

---

##核心原理

本体是**不固定**。类型和关系在文档被摄取时出现。
然而，本体必须保持紧凑、一致和可重用。

---

##实体类型规则

# # #正常化

当分配一个实体类型时，应用这些转换：
1. 转换为小写的**
2. 条带leading/trailing空格
3. 将“_”和“-”替换为空格
4. 使用下面的映射表合并同义类型

同义词映射（实体类型）

|变体|标准类型||---------|---------------|
|组件，模块，类，功能|组件|
bug，缺陷，fault, error, failure
|服务器、主机、机器、节点|基础设施|
|用户、人员、操作员、管理员、参与者|参与者|
b|应用、应用、服务、程序、软件|软件|
|数据库，数据存储，db，存储|存储|
| api，端点，接口，连接|接口|
|事件，事件，发生，触发|事件|
概念，概念，原则，理论
|进程，线程，任务，作业，工作流|进程|

添加新类型

如果一个实体不匹配任何现有的类型：
-创建一个新的类型，如果它是真正不同的
保持标签简短（1-3个单词，小写）
—在创建新类型之前，请考虑现有类型是否足够接近

# # #约束-整个本体中最多~50个不同的实体类型
—如果接近极限，则合并相似的类型，而不是创建新的类型

关系类型规则

# # #正常化

在分配关系类型时：
1. 转换为小写的**
2. 带空格
3. 使用现在时的动词短语（例如，“cause”，“contains”，“uses”）
4. 使用下面的映射表合并同义词

同义词映射（关系类型）

|变体|规范关系||---------|-------------------|
|触发，导致，结果，产生|导致|
|是|的一部分，属于|，住在|，坐在|包含|
|依赖于|
|使用、调用、调用、消费|使用|
|影响，影响，影响|影响|
|创建，实例化，生成|创建|
|连接到|
|继承、扩展、子类|扩展|
|读取，查询，获取|读取|
|写入，存储，持久化到|写入|

添加新的关系

—只有在现有类型不能准确描述关系时，才添加新的关系类型
-更喜欢规范关系，而不是创建新的关系

---

本体更新协议

处理时，从`ingestion.md`中提取entities/relations：

1. 对于每个实体类型：
—运行同义词映射
-调用`ontology_store.normalize_type(type_name)`获取规范形式
—调用`ontology_store.add_type(canonical_type)`进行注册2. 对于每个关系类型：
—运行同义词映射
-调用`ontology_store.normalize_relation(relation_name)`以获得规范形式
—调用`ontology_store.add_relation(canonical_relation)`进行注册

3. 在图中创建节点和边时，使用**规范的**type/relation名称。
