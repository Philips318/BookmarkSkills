# Doublecheck

在ai生成的输出上运行一个三层验证管道。目标不是告诉用户什么是真的——而是提取每一个可验证的声明，找到用户可以独立检查的来源，并标记任何看起来像幻觉模式的东西。

# #激活

双重检查有两种模式：**活动模式**（持久）和**一次性模式**（按需）。

###激活模式

当用户调用此技能而不提供特定文本进行验证时，激活持久的双重检查模式。回复:

> **双重检查现在是活跃的。在陈述之前，我会核实我的回答中的事实主张。您将在每个实质性响应之后看到一个内联验证摘要。对任何回复说“完整报告”，以获得完整的三层验证和详细的来源。随时通过说“关闭双重检查”来关闭它。然后在接下来的对话中遵循以下所有规则：

**规则：在发送之前对每个回复进行分类

在作出任何实质性答复之前，确定其中是否包含可证实的主张。将回应分类：

|响应类型|包含可验证的声明？|动作||--------------|---------------------------|--------|
|事实分析、法律指导、监管解释、合规指导，或包含案例引用或法定参考的内容|是-高密度|运行完整的验证报告（见下面的高风险内容规则）|
|文档、研究或数据的摘要|是—中等密度|对关键声明|运行内联验证
|代码生成，创意写作，头脑风暴|很少|跳过验证；注意，双重检查模式不适用于这种类型的内容|
|随意交谈，澄清问题，状态更新|否|静默跳过验证|

**规则：活动模式的内联验证

当应用活动模式时，不要为每个响应生成单独的完整验证报告。相反，使用以下模式将验证直接嵌入到您的响应中：1. 正常回复。
2. 在响应之后，添加一个`Verification`节。
3. 在该部分中，列出每个可验证的声明及其可信度评级和可用的来源链接。

格式:```
---
**Verification (N claims checked)**

- [VERIFIED] "Claim text" -- Source: [URL]
- [VERIFIED] "Claim text" -- Source: [URL]
- [PLAUSIBLE] "Claim text" -- no specific source found
- [FABRICATION RISK] "Claim text" -- could not find this citation; verify before relying on it
```
对于活动模式，优先考虑速度。在网上搜索引文、具体的统计数据，以及任何你不太相信的说法。你不需要搜索那些常识或你对其非常有信心的说法——只要认为它们是可信的，然后继续。

如果任何索赔率有争议或捏造风险，请在验证部分之前突出显示，以便用户立即看到。当应用自动升级（见下文）时，将此标注放在完整报表的顶部，汇总表之前：```
**Heads up:** I'm not confident about [specific claim]. I couldn't find a supporting source. You should verify this independently before relying on it.
```
**规则：对高风险发现自动升级到完整报告

如果您的在线验证识别任何索赔评级争议或制造风险，不要进行在线验证。相反，将“Heads up”标注放在响应的顶部，然后使用`assets/verification-report-template.md`中的模板生成完整的三层验证报告。当某些地方明显出错时，用户不应该要求提供详细的报告。

**规则：高风险内容的完整报告

如果响应包含法律分析、法规解释、遵从性指导、案例引用或法定参考，请始终使用`assets/verification-report-template.md`中的模板生成完整的验证报告。不要对这些内容类型使用内联验证——简化格式的风险太高了。

**规则：内联验证的可发现性页脚当生成内联验证（不是完整的报告）时，总是在验证部分的末尾添加这一行：```
_Say "full report" for detailed three-layer verification with sources._
```
**规则：应要求提供全面验证

如果用户说“完整报告”、“运行完整验证”、“验证那个”、“双重检查那个”或类似的话，那么运行完整的三层管道（下面描述），并使用`assets/verification-report-template.md`中的模板生成完整报告。

###一次性模式

当用户调用此技能并提供特定文本来验证（或引用以前的输出）时，运行完整的三层管道，并使用`assets/verification-report-template.md`中的模板生成完整的验证报告。

# # #失活

当用户说“关闭双重检查”、“停止双重检查”或类似的话，你可以这样回应：

> **双重检查现在关闭。**我将在没有内联验证的情况下正常响应。你可以随时重新激活它。

---

第1层：自我审计

用批判的眼光重新阅读目标文本。你在这一层的工作是提取和内部分析——还没有网络搜索。###步骤1：提取索赔

逐句通读目标文本，找出每一个可以证实的陈述。对每项索赔进行分类：

|类别|寻找什么|示例||----------|-----------------|---------|
|“Python创建于1991年”，“GPL要求衍生作品是开源的”| **事实** |关于事物如何或如何的断言|
|数字、百分比、数量|“95%的企业使用云服务”，“合同有30天终止条款”|
| **引文** |对特定文件、案例、法律、论文或标准的参考|“根据CDA第230条…”，“In *Mayo v. Prometheus*(2012)…”|
|“OpenAI是由Sam Altman和Elon Musk创立的”，“GDPR适用于欧盟居民”|
|声称X导致Y或X导致Y |“此漏洞允许远程代码执行”，“该法规是为了应对2008年金融危机而通过的”|
|日期，时间线，事件序列|“截止日期是3月15日”，“2.0版本发布了。在安全补丁“|”之前使用为每个索赔分配一个临时ID （C1、C2、C3…），以便在后续层进行跟踪。

步骤2：检查内部一致性

相互审查提取的索赔要求：
-文本是否有自相矛盾的地方？（例如，为同一事件陈述两个不同的日期）
-是否有逻辑上不相容的主张？
-文章是否在某一节中做出了与另一节相矛盾的假设？

立即标记任何内部矛盾——这些不需要外部验证来识别问题。

步骤3：初始置信度评估对于每一项索赔，仅根据自己的知识进行初步评估：
-你记得这是准确的吗？
-这是模型经常产生幻觉的说法吗？（具体的引用、精确的统计和确切的日期是高风险类别。）
-该声明是否明确到足以验证，还是模糊到无法证伪？

记录你最初的信心，但不要将其作为发现报告。这是第2层的输入，不是输出。

---

第二层：源验证

对于每一个提取出来的主张，寻找外部证据。这一层的目的是找到用户可以访问的url来独立验证声明。

搜索策略

对于每一项索赔：1. **制定一个搜索查询**，将显示主要来源。对于引用，搜索确切的标题或案例名称。对于统计数据，搜索特定的数字和主题。对于事实主张，搜索关键实体和关系。

2. **使用`web_search`运行搜索**。如果第一次搜索没有返回相关的结果，重新制定并使用不同的术语再次尝试。

3. 评估你的发现：**
-你是否找到了一个主要的或权威的来源来直接解决这个问题？
-你是否从可靠来源发现了相互矛盾的信息？
-你没找到相关的吗？（这本身就是一个信号——真实的东西通常都有网络足迹。）

4. **记录结果**与源URL。始终提供URL，即使您还总结了源代码的内容。

什么是源更喜欢原始和权威的消息来源：
—官方文档、规范和标准
-法庭记录，立法文本，监管文件
-经同行评审的刊物
-官方组织网站和新闻稿
-已建立的参考文献（百科全书、法律数据库）

注意来源是次要的（新闻文章、博客文章、维基页面）还是主要的。用户可以相应地称重。

###具体处理引用

引用是导致幻觉的最高风险类别。对于任何引用特定案例、法规、论文、标准或文件的主张：1. 搜索确切的引用（案例名称、标题、章节号）。
2. 如果你找到了，确认引用的内容确实说了目标文本声称的内容。
3. 如果你根本找不到它，就把它标记为制造风险。模型经常为不存在的事物产生看似合理的引用。

---

第3层：对抗性审查

完全改变你的姿势。在第1层和第2层中，您试图理解和验证输出。在这一层中，**假设输出包含错误**并主动尝试找到它们。

幻觉模式检查表

检查这些常见的模式：

1. **捏造的引用**——文本引用了一个特定的案例、论文或法规，而你在第2层中找不到。这是最危险的幻觉模式，因为它看起来很权威。2. **没有来源的精确数字**——文本陈述了一个特定的统计数据（例如，“78%的公司……”）没有说明数字的来源。模型经常产生听起来似乎合理的统计数据，但这些数据完全是编造出来的。

3. **对不确定主题的自信特异性** -文本陈述的内容非常具体，具体内容是真正未知或有争议的主题。注意准确的日期，精确的金额，以及专家不同意的领域的明确归属。

4. **看似合理但错误的关联**——文本将概念、规则或事件与错误的实体联系起来。例如，把一项裁决归因于错误的法院，把一段话引用给错误的人，或者在正确描述法律名称的同时错误地描述了法律的条款。5. **时间混乱**——文本描述的事物可能是过时的，或者以错误的顺序描述了一系列事件。

6. **过度概括** -文本陈述的东西是普遍正确的，当它只适用于特定的司法管辖区，上下文，或时间段。常见的法律法规内容。

7. **缺少限定词** -文本提出了一个微妙的话题作为解决或直接当显著的例外，限制，或反驳存在。

对抗性问题

对于通过第1层和第2层的每个主要索赔，问：
-这种说法有什么错？
在这方面是否存在一种普遍的误解，认为模型可能已经捡起了？
-如果我是一个主题专家，我会反对这种说法吗？
-这个声明是在我的训练数据截止之前还是之后，是不是已经过时了？

###升级危险信号如果你发现了其中的任何一种，在报告中显著地标记出来：
-在任何地方都找不到的特定引用
-没有可识别来源的统计数据
-与权威来源的说法相矛盾的法律或监管主张
-一种有高度可信度的声明，但实际上存在争议或不确定

---

生成验证报告

完成所有三个层之后，使用`assets/verification-report-template.md`中的模板生成报告。

信心评级

为每项索赔分配最终评级：

|评级|含义|用户应该做什么||--------|---------|------------------------|
| **已验证** |找到支持源并链接|如果声明对您的工作至关重要，请抽查源链接|
| **似是而非** |符合常识，未发现具体来源|视为合理但未经证实；独立验证是否依赖于它来做决定b|
b| **未经证实** |找不到支持或反驳的证据|未经独立核实请勿依赖此声明|
| **有争议** |从可靠来源发现矛盾的证据|审查矛盾的来源；这种说法可能是错误的
| **捏造风险** |符合幻觉模式（例如，找不到引用，来源不明的精确统计数据）|假设这是错误的，直到你能从主要来源确认它|

报告原则-提供链接，而不是结论。用户决定什么是真实的，而不是你。
-当你发现矛盾的信息时，向双方提供来源。不要选择赢家。
-如果一个主张是不可证伪的（太模糊或太主观而无法证实），就说出来。“不可证伪”是有用的信息。
-明确哪些是不能检查的。“我无法证实这一点”和“这是错的”是不同的。
-按严重程度对发现进行分组。从最需要关注的项目开始。

###限制披露

总是在报告的最后加上这句话：b> **本验证的局限性：**
> -该工具加速人工验证；它不能取代它。
> -网络搜索结果可能不包括最新的信息或付费来源。
> -对抗性审查使用可能产生原始输出的相同底层模型。它捕获了许多问题，但不能捕获所有问题。
> -被评为已验证的声明意味着找到了支持来源，而不是声明绝对正确。消息来源也可能是错误的。
b> -被评为可信的索赔可能仍然是错误的。没有反驳的证据并不能证明其准确性。

领域特定的指导

法律内容法律内容会增加产生幻觉的风险，因为：
-案例名称、引用和持有情况经常由模型捏造
-管辖权的细微差别经常被淡化或省略
-法定语言可能以改变法律含义的方式被改写
-“多数决定”和“少数决定”的区别经常被忽略

对于法律内容，请额外仔细检查：案例引用、法定参考、法规解释和管辖权要求。尽可能搜索法律数据库。

###医学和科学内容

-检查被引用的研究是否真实存在，结果是否被准确描述
-注意过时的指导方针是否被视为最新的
-标记剂量、治疗方案或诊断标准——这些变化和错误可能是危险的

金融和监管内容-验证具体的金额、日期和阈值
-检查法规要求是否属于正确的管辖范围，并且是最新的
-注意在最近的立法变化后可能过时的税法声明

###技术和安全内容

—检查CVE编号、漏洞描述和受影响的版本
-检查API规范和配置说明是否与当前文档匹配
-注意可能过时的版本特定信息
