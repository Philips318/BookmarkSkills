🎯 亮点：Harness 主动抓出的 3 个真实缺陷Highlight: 3 Real Defects the Harness Caught

这是本次实验最有价值的证据：单元测试与 BDD 全绿，但 harness 的隔离评估和演示 Gate仍抓出了 3 个真实缺陷——正好印证「生成 ≠ 评估」与「演示 Gate」的价值。This is the experiment's most valuable evidence: unit and BDD tests were green, yet the harness's isolated evaluation and demo gate still caught 3 real defects — validating the "generation ≠ evaluation" and demo-gate principles.

① dev-evaluator · T01 基础设施评估 FAILInfrastructure eval FAIL FIXED

  • 发现：DicomDisplayTags 字段缺 XML 文档；QMS 的 SDD/MVP/MVProcedure 必填章节为空；缺 VerificationTests.sln。Found: missing XML docs on DicomDisplayTags fields; QMS SDD/MVP/MVProcedure required sections empty; missing VerificationTests.sln.
  • 意义：评估器强制了「代码文档 + 活体 QMS」纪律，而非只看测试是否通过。Why it matters: the evaluator enforced "code docs + living QMS" discipline, not just green tests.

② dev-evaluator · T04 撤销任务评估 FAIL（3 个发现）Undo task eval FAIL (3 findings) FIXED

  • 功能 Bug：IsSeriesLoaded 由「是否有有效缺省窗宽」推导 → 无 DICOM 标签/非法 WW 的序列会让复位按钮被错误禁用，违反 FR-01/04/07。Functional bug: IsSeriesLoaded was derived from "has valid default WW" → a series without DICOM tags / invalid WW wrongly disabled the Reset button, violating FR-01/04/07.
  • 静默跳过的 BDD：Reqnroll 把步骤里的 /（Window/Level）当成 Cucumber「或」运算符 → 步骤永不匹配 → 场景被静默跳过而非报错。Silently skipped BDD: Reqnroll treated / in the step (Window/Level) as a Cucumber "OR" operator → step never matched → scenario silently skipped instead of failing.
  • 弱测试：有界深度撤销测试只验证「上限 20」，未证明「淘汰最旧项」→ 已强化为断言淘汰顺序。Weak test: the bounded-depth undo test only checked the "cap of 20", not "evicts the oldest" → strengthened to assert eviction order.

③ feature-demonstrator · Gate 3 演示时发现 WPF 集成缺陷WPF integration defect found at demo FIXED

  • 现象：复位后撤销按钮仍禁用、无法点击（而所有单元/BDD 测试都通过）。Symptom: after a reset the Undo button stayed disabled and couldn't be invoked (yet all unit/BDD tests passed).
  • 根因：自定义 DelegateCommand 在 UI 无关的 net8.0 库里，钩不到 WPF 的 CommandManager.RequerySuggested；复位路径没触发 CanExecuteChanged。测试通过是因为它们直接调 CanExecute(null)，绕过了 WPF 的事件式重查询。Root cause: the custom DelegateCommand in the UI-agnostic net8.0 library can't hook WPF's CommandManager.RequerySuggested; the reset path never fired CanExecuteChanged. Tests passed because they call CanExecute(null) directly, bypassing WPF's event-driven requery.
  • 意义（关键）：这正是只有真机演示能抓到、纯测试抓不到的集成缺陷——证明演示 Gate 不可或缺。修复后重跑演示，撤销/重做均正常。Why it matters (key): exactly the kind of integration defect only a live demo catches, not pure tests — proving the demo gate is indispensable. After the fix, the re-run demo showed undo/redo working.
