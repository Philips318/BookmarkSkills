Strengthen

Peng 方案如何强化（吸收 Kunal 之长）How to strengthen Peng's harness (absorb Kunal's strengths)

  • 引入自主执行内核：把 Orchestrator 升级为「生成/评估循环 + 3× 重试预算 + 定义缺陷向下级联」。
  • Adopt an autonomous core: upgrade the Orchestrator to a "generate/evaluate loop + 3× retry budget + definition cascade".
  • 加隔离式 Evaluator：新增独立上下文的评估角色，跑全部测试、只判质量、不写测试。
  • Add an isolated evaluator: a fresh-context role that runs all tests, only judges quality, authors no tests.
  • 补黑盒测试设计者：新增 test-designer（盲测）+ FlaUI/UI 自动化技能，端到端打到 UI 层。
  • Add a black-box test-designer: blind test-designer + FlaUI/UI skills to reach the UI layer end-to-end.
  • 升级状态存储：把 artifacts/ 扩为 .harness/ 式（backlog schema、eval_feedback、tool_outputs、progress）。
  • Upgrade the state store: extend artifacts/ to a .harness/-style store (backlog schema, eval_feedback, tool_outputs, progress).
  • 接活体 QMS 管线：把 doc-generator/ifu 产出接上 md→docx 导出与结构校验。
  • Wire the living-QMS pipeline: connect doc-generator/ifu output to md→docx export + structure checks.
  • 路径触发 instructions：从只作用 .cs，扩到按 Src/**、Build/**、状态目录自动触发。
  • Path-triggered instructions: from only .cs to auto-firing on Src/**, Build/**, and state dirs.

Verdict

Peng 的 Harness 是一套「懂医疗、懂标准、能自愈、能出报告」的深度知识资产；短板恰是自主长跑执行、隔离评估与 UI 测试闭环——而这正是 Kunal 的强项。Peng's harness is a deep knowledge asset that "understands medicine & standards, self-heals, and reports"; its gaps — autonomous long-run execution, isolated evaluation, UI test loop — are exactly Kunal's strengths.
